# 02 — 单仓库任务与 pi 会话

**What to build:** 用户在桌面中注册一个已有仓库，创建独立任务，与 pi 对话并修改任务代码，关闭后可恢复任务和会话。

**Blocked by:** 01 — 可见浏览器控制原型，明确桌面集成路线。

**Draft:** 待拆分审阅，未发布。

**Parent:** [首版规格](../spec.md)。

- [ ] 桌面基础界面遵循规格中的视觉要求：不使用绿色作工作台强调色、状态色或图表色；π 标记居中。当前蓝灰原型作为设计基线，整体 A/B/C 布局仍待 UI 审阅，不直接将原型代码提升为产品实现。
- [ ] 创建项目并绑定已有仓库，按规格「任务目录与远程基线」选择远程分支；创建前 fetch 并固定此次获取的提交，再建立独立分支/worktree；不依赖旧基线，不对主检出目录执行 pull/merge/reset。
- [ ] 中文显示名称、自动英文数字目录标识和可编辑任务分支分别保存；本机设置持久化默认任务根目录，新建可单次覆盖并预览实际路径。任务保存实际根目录，默认值变化或重开不会迁移已有任务；路径不可用和标识冲突明确处理。
- [ ] 获取失败保留表单及重试入口，不从旧引用创建；文件面板显示实际目录、远程基线与创建提交，主检出目录未提交工作保持原状。
- [ ] 显示任务名称、仓库、分支、准备状态及基本代码变化；异常信息关联到具体任务。
- [ ] 用户能配置 pi 支持的模型与本机凭据，发送消息，看到流式回复和工具结果，并中止当前执行。
- [ ] 从首个模型调用开始提供稳定调用身份，保留实际 Provider 配置、模型、usage 来源和事件；为后续多 Provider 和用量统计提供可恢复记录，不只保存渲染后的消息文本。
- [ ] pi 的代码工具使用当前任务的工作目录和允许访问的仓库范围；默认不能把写入目标回退到原检出目录。
- [ ] UI 与 Agent 共用任务操作入口；基础执行采用单会话，持有任务写操作权直到相关工具与子进程结束。
- [ ] 任务和会话分别持久化，重新打开任务恢复指定会话，不错误接续另一个任务最近的会话。
- [ ] 保留用户输入与发送记录的关联，持久格式可容纳后续结构化引用、技能来源和未发送草稿，不只依赖聊天界面的渲染文本恢复输入。
- [ ] 用临时仓库验证 Agent 修改只落入该任务；模型故障或取消不丢失已有消息与代码。

- [ ] pi 统一以任务文件夹作为启动 cwd，各 worktree 位于其下；数据与工具边界可由 03 扩展普通目录来源，不将项目固化为单个 Git 仓库。

**验证方式：** 完整演示创建任务、一次有文件修改的 pi 对话、中止和重开恢复；模型外的关键行为使用可重复执行的测试替身验证，另记录实际模型联通结果。
