# 07 — 真实对账单详情同步验证

**What to build:** 使用用户指定仓库，在任务内浏览器打开现有 SaaS 对账单详情，查询经过本地 BFF、本地 invoice 和 shipment，并呈现可追溯结果。

**Blocked by:** 05 — 多服务联动与运行状态；06 — Agent 控制任务浏览器。

**Draft:** 待拆分审阅，未发布。

**Parent:** [首版规格](../spec.md)。

**Context:** [真实页面与调用链](../../../docs/pilot-synchronous-query.md)、[仓库核对](../../../docs/pilot-repository-inspection.md)。

- [ ] 准备用户选择的非生产环境与已有对账单，使用实际登录和动态菜单；不假设源码中存在固定页面 URL。
- [ ] 图形化导入并核对主壳、BFF、invoice、shipment 配方，远程账号等必要依赖可达；协议保留既有发布版本。
- [ ] 用户完成登录后，Agent 通过可见菜单进入消费流水，点击已有对账单并等待详情结果。
- [ ] 记录 GetReconciliationInvoices 及详情字段引发的本地 invoice/shipment 调用，检查 GraphQL 错误而非只检查 HTTP 状态。
- [ ] 网络目标、本地 RPC 日志和运行实例相互关联；缺少证据时明确标为未证明，不以旧 REST 列表成功替代。
- [ ] 第二个任务并行执行同一流程，地址和浏览器状态独立；共享数据的相同查询结果不作为隔离失败。
- [ ] 在任务内实施一处可观察、无共享数据写入的局部变化并重新加载后验证新实例，另一任务不受影响；变化可审阅和撤回。
- [ ] 远程前提阻塞时分别报告已通过的本地部分和缺失条件；直接 GraphQL 调用只能辅助排查，不能标记完整 UI 用例通过。

**验证方式：** 完整真实页面操作、同步 RPC 证据及双任务对照；不启动 worker、scheduler 或 DTM 工作流来替代这一同步用例。
