# 04 — 图形化环境配置与单服务运行

**What to build:** 用户从现有配置导入草案，在界面选择环境、编辑变量并启动一个任务服务；Agent 使用相同配置执行同一操作。

**Blocked by:** 02 — 单仓库任务与 pi 会话。

**Draft:** 待拆分审阅，未发布。

**Parent:** [首版规格](../spec.md)。

- [ ] 按环境编辑共享模板，维护一个服务的启动命令、参数、工作目录、端口与健康检查；业务默认配置由服务自行读取。
- [ ] 从现有编辑器配置与启动脚本提取草案，区分常驻服务、一次性命令和准备步骤；显示无效变量及待核对项。
- [ ] 凭据及本机路径单独保存，导入含敏感值的配置时不写入共享模板；界面和 Agent 输出显示变量来源与遮蔽值。
- [ ] 按确定的优先级解析环境、本机和任务值，缺失引用或冲突明确报错；每个子进程获得独立环境，不修改应用全局变量。
- [ ] UI 与 Agent 都能启动、停止服务，查看有限日志及健康状态；基本状态不把依赖可达等同于进程存活。
- [ ] Agent 修改共享模板生成差异确认，任务临时覆盖可自动调整；已有任务保留模板版本，显式更新列出需重启项。
- [ ] 桌面启动使用明确的程序与参数，不依赖 Unix 专属的内联环境赋值；记录各平台实际验证情况。

**验证方式：** 用能回报实际生效配置的受控服务验证覆盖关系，再对真实仓库生成脱敏导入草案。包含失效变量、私有路径和进程退出的行为验证。
