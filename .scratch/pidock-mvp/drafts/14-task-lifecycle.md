# 14 — 后台、恢复、归档与清理

**What to build:** 任务可在关闭窗口后继续运行，在明确退出后安全停止，并能恢复、归档或清理所有所属资源。

**Blocked by:** 08 — 任务内协议生成与消费者绑定；13 — 对话引用、技能与符号命令。

**Draft:** 待拆分审阅，未发布。

**Parent:** [首版规格](../spec.md)。

- [ ] 关闭窗口后继续 Agent 与服务执行，并有明确后台入口重新打开；跨平台行为符合已确认规则。
- [ ] 明确退出先中止 Agent，再停止所属服务、终端及子进程树，保存状态；退出失败可定位且不静默丢失任务。
- [ ] 再次启动恢复任务、会话和浏览器状态；服务由用户或 Agent 重新启动，不自动连接业务环境。
- [ ] 保留各会话结构化草稿及历史引用来源，恢复时重新校验文件和技能可用性；不自动发送草稿、展开新内容替换历史或再次执行命令。
- [ ] 异常退出后验证现存进程和 Git 资源身份，不只凭过期 PID 或端口认领/停止进程。
- [ ] 归档停止运行并保留代码、会话、模板版本、生成绑定记录及浏览器状态，支持恢复。
- [ ] 清理独立于归档，显示未提交/未交付代码、会话和浏览器数据的处理范围；未明确处理的数据保持可恢复。
- [ ] 只移除身份可确认的任务资源，拒绝接管或删除未知目录、原检出目录及另一任务资源。
- [ ] 局部清理失败保留准确状态与恢复入口，不以清空元数据掩盖残留。
- [ ] 归档和恢复不清零或重复累计 Token；清理对话时展示用量记录的处理范围，不因历史文件被删除而静默改变已有统计。

- [ ] 恢复每个会话的权限选择及请求实际采用的权限记录，不自动升权、不因恢复重放待审批或已执行的操作；取消、异常恢复与在途执行保持明确关联。

- [ ] 归档／恢复保留普通目录来源、链接名及任务位置；清理只移除身份确认的任务内链接，永不沿链接删除原始目标。用有内容的原目录验证清理后文件完整，覆盖链接失效、外部改指、循环及局部清理失败。

**验证方式：** 正常退出、强制中断、恢复、归档和局部清理失败的端到端演示；覆盖有未提交工作和被外部替换的资源。
