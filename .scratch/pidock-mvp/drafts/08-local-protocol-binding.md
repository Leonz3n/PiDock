# 08 — 任务内协议生成与消费者绑定

**What to build:** 用户修改任务中的协议后，可在界面准备本地生成物并绑定同任务消费者，无需先发布包即可编译、运行和验证。

**Blocked by:** 05 — 多服务联动与运行状态。

**Draft:** 待拆分审阅，未发布。

**Parent:** [首版规格](../spec.md)。

**Context:** [apis 与消费者现状](../../../docs/pilot-repository-inspection.md)。

- [ ] 区分协议仓库、生成步骤和消费者绑定，界面显示准备状态与实际生成版本。
- [ ] 协议未改动时保留发布依赖；选择本地联调时在本任务生成目录执行完整生成与后处理。
- [ ] Go 消费者通过任务专属 workspace 或等效临时绑定使用本地模块；避免无意合并其他服务的依赖版本选择或回写发布配置。
- [ ] TS 消费者使用现有受管理链接方式，链接、依赖目录和标记属于当前任务；重新安装后可检查并恢复绑定。
- [ ] 编译前确认解析路径；不同发布版本切换到同一本地产物出现不兼容时停止并解释。
- [ ] 协议再次变化使相关消费者标记为需要重新生成/编译/启动，旧运行实例不会被当作已加载新协议。
- [ ] 切回发布依赖能恢复原有解析，另一个任务的依赖不变。
- [ ] 检查所需生成工具，提供平台具体结果；Windows ARM64 等已知工具缺口必须明确处理，不能由桌面本身可启动推断生成支持。

**验证方式：** 使用同任务真实协议与消费者完成本地解析、编译和一条可观察调用；同时检查另一任务保留自己的发布/本地依赖。
