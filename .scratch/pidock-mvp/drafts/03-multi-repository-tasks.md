# 03 — 混合目录任务与 Git 工作副本隔离

**What to build:** 用户在项目中维护仓库和普通目录，创建混合或纯目录任务并追加资源；Git 采用独立 worktree，普通目录以软链接共享原文件。

**Blocked by:** 02 — 单仓库任务与 pi 会话。

**Draft:** 待拆分审阅，未发布。

**Parent:** [首版规格](../spec.md)。

- [ ] 一个项目维护多个仓库与普通目录，任务选择其中一部分；每仓库可选择不同远程及基线分支，例如 origin/main、upstream/release/v2。
- [ ] 延续 02 的目录规则：在指定根目录下创建独立英文数字任务目录，各仓库位于其下；追加沿用任务保存的根目录和标识，不采用后来修改的本机默认目录。
- [ ] 创建／追加前先 fetch 本次所选远程分支，全部获取成功后按逐仓库固定的完整提交创建分支/worktree，记录并展示来源；不以本地旧分支或缓存引用代替。追加只处理新增仓库，已有基线和运行状态保留。
- [ ] 远程获取失败时标明仓库和原因，保留表单并支持重新获取；不创建工作副本，不回退旧基线。覆盖认证失败、网络失败、远程分支删除／强推，以及多任务获取时固定提交不被串用。
- [ ] 创建与追加仓库都准备独立分支/worktree，更新任务视图和 Agent 可见仓库；忙碌会话在明确边界刷新资源，不静默重绑定。
- [ ] 展示两个任务共享的仓库各自独立的路径、分支及变化；Git worktree 内写入一个任务不影响另一个；此隔离不适用于普通目录链接的共享目标。
- [ ] 路径已被占用、分支已在其他 worktree 使用或仓库不可用时，显示具体冲突，不接管未知资源。
- [ ] 跨仓库准备部分失败或应用中断后，可辨识已创建资源与未完成项，恢复时保留用户修改。
- [ ] 仓库级元数据操作有适当协调；两个任务并发创建共享仓库的 worktree 不产生相互覆盖。

- [ ] 按规格「混合目录与任务软链接」实现项目普通目录条目及任务混选／纯目录创建／追加；普通目录不要求 Git 或环境，不自动初始化仓库，均保留任务文件夹和根目录校验。
- [ ] 普通目录使用稳定 ASCII 链接名，保存来源快照和链接身份；预览 worktree／链接路径及原始目标，追加保留旧入口与 Git 基线。仅获取新增 Git 仓库，获取全部成功后才准备资源。
- [ ] 用真实 pi 验证统一 cwd 下普通链接的列举、搜索、读取和写入；验证修改影响原目标，不冒充独立副本。两平台链接能力、名称冲突、失效／嵌套／循环目标、部分准备失败及恢复分别记录。
- [ ] 跨任务／项目共享普通目标的写协调方案须在实现该共享访问前细化；与 09 对接真实路径授权和写协调，不能用任务 ID 锁或不同链接名称声称文件隔离。

**验证方式：** 使用可控远程及故意落后的本地分支／跟踪引用，以两个重叠的多仓库任务执行创建、追加、修改、获取失败和部分创建失败恢复。检查实际创建提交、目录及界面来源一致，默认根目录变化不迁移任务，原检出目录与另一任务不变。
