# 01 — 可见页面控制与桌面壳技术验证

**What to build:** 用户能看见并接管自动化正在操作的内嵌页面；在同一桌面原型中验证两个任务的页面与登录状态隔离；同时用运行证据确认 Electrobun ＋ Bun 主进程 ＋ CEF 渲染器的路线成立，为后续工单冻结桌面集成方式。

**Blocked by:** None — can start immediately.

**Status:** needs-triage

**状态说明：** 技术验证本身已经完成；因候选路线触发回退关卡，父计划需要据此重新拆分 Electron + Bun Host 验证/实现工单。

**执行状态：** 验证完成；Electrobun 2.0.1 路线未通过决策关卡，结论为回退 Electron + Bun Host。正式报告见 [可见页面控制与桌面壳验证](../../../docs/browser-automation-validation.md)。

**Parent:** [首版规格](../spec.md)。技术栈与运行时见规格「技术栈与运行时」。

- [x] 原型只回答三个问题：内嵌可见页面能否被可靠控制、两个任务的页面与登录状态能否隔离、选定的桌面壳与渲染器组合是否成立。产出可重复的演示步骤和技术结论；受控页面测试不替代真实业务验收。
- [x] 桌面壳以 **Bun 执行主进程**，记录实际 Bun 版本与 Electrobun 版本，并显式配置 Bun 模式、验证打包后运行时；自有界面与任务页面在同一窗口内同时可见，且分别是系统 webview 与 CEF 渲染器。
- [x] 自动化操作用户看见的同一页面，按角色/标签填写控件，等待异步变化；不得用另一个隐藏浏览器、`Bun.WebView` 的 headless 视图或另一个 WebView 的成功代替。
- [ ] 持久化 `partition` 按任务分配，页面句柄按视图分配并绑定任务；同任务的两个标签页与登录弹窗复用任务分区，验证 Cookie／同源 localStorage 共享及弹窗登录回到原页。两个任务同站点使用不同账号或标记，重启后互不覆盖；重开标签不丢登录，关闭视图不删除分区，关闭一个任务不影响另一个。不要求页面级 sessionStorage 跨标签共享。**部分通过：共享、隔离、弹窗回传和重启持久化有证据；关闭单个 CEF view 会清理全部 CEF views，无法验证原位重开。**
- [x] 通过 CEF 调试协议接入获得按需证据：语义定位与可操作性等待、截图、相关控制台错误与失败请求。输出有界，避免每步转储全部内容。**不能假设 Electrobun 提供完整的自动化证据 API**，因此这条只有实测通过才算成立。
- [x] 记录 `view.executeJavascript()` 不返回求值结果这一限制的实际规避方式（注入脚本加 RPC，或直接走调试协议），并说明对定位、等待与断言写法的影响。
- [x] 人工接管暂停后续自动化操作，恢复时重新读取页面状态；页面关闭、弹窗、iframe、下载及开发者工具开关有明确失效／恢复行为，并分别记录是否通过。
- [ ] 记录 CEF 与系统 webview 的安装包体积、启动时间差异，以及开启 CEF 调试端口后本机新增的监听面与其边界。**部分完成：已实测解包 development `.app` 体积、启动标记和监听面；未产出安装器，不能称为安装包体积。**
- [x] macOS/Windows 分别记录实测结果与待测项；没有可用 Windows 环境时保留明确的平台验证关卡，不能声称跨平台通过。

- [x] 记录选定版本的 macOS arm64 DMG 与 Windows x64 单一 EXE 产出、签名和公证路径；Windows Setup ZIP 不能直接视为 EXE 交付，检查安装 payload 完整性。实际发布验收归 15。参考[运行时调研](../../../docs/desktop-runtime-research.md)。

**决策关卡：已触发。** CEF 调试接入可提供语义操作和按需证据，但 Electrobun 2.0.1 在 macOS arm64 上无法可靠初始化新 partition 的首个 CEF view，且移除一个 CEF view 会清理同窗全部 CEF views。PiDock 回退到 Electron 桌面壳（主进程运行其内置 Node）加 Bun Host；保留任务/页面句柄、partition 命名、Bun Host 与 React 界面边界，并以相同场景重新验证 Electron。证据和受影响设计见正式报告。

**验证方式：** 端到端驱动两个可见页面，断言实际 DOM 变化、独立存储和错误证据，并记录桌面壳与渲染器的实际组合。技术失败先修订方案，不直接进入产品集成。
