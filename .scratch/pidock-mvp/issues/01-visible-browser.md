# 01 — 可见页面控制与桌面壳技术验证

**What to build:** 用户能看见并接管自动化正在操作的内嵌页面；在同一桌面原型中验证两个任务的页面与登录状态隔离；同时用运行证据确认 Electrobun ＋ Bun 主进程 ＋ CEF 渲染器的路线成立，为后续工单冻结桌面集成方式。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

**Parent:** [首版规格](../spec.md)。技术栈与运行时见规格「技术栈与运行时」。

- [ ] 原型只回答三个问题：内嵌可见页面能否被可靠控制、两个任务的页面与登录状态能否隔离、选定的桌面壳与渲染器组合是否成立。产出可重复的演示步骤和技术结论；受控页面测试不替代真实业务验收。
- [ ] 桌面壳以 **Bun 执行主进程**，记录实际 Bun 版本与 Electrobun 版本；自有界面与任务页面在同一窗口内同时可见，且分别是系统 webview 与 CEF 渲染器。
- [ ] 自动化操作用户看见的同一页面，按角色/标签填写控件，等待异步变化；不得用另一个隐藏浏览器、`Bun.WebView` 的 headless 视图或另一个 WebView 的成功代替。
- [ ] 两个任务使用不同持久化 `partition`；同站点分别登录或保存测试标记，重启后互不覆盖，关闭一个任务不影响另一个。
- [ ] 通过 CEF 调试协议接入获得按需证据：语义定位与可操作性等待、截图、相关控制台错误与失败请求。输出有界，避免每步转储全部内容。**Electrobun 本身不提供截图、控制台与网络捕获 API**，因此这条只有实测通过才算成立。
- [ ] 记录 `view.executeJavascript()` 不返回求值结果这一限制的实际规避方式（注入脚本加 RPC，或直接走调试协议），并说明对定位、等待与断言写法的影响。
- [ ] 人工接管暂停后续自动化操作，恢复时重新读取页面状态；页面关闭、弹窗、iframe、下载及开发者工具开关有明确失效／恢复行为，并分别记录是否通过。
- [ ] 记录 CEF 与系统 webview 的安装包体积、启动时间差异，以及开启 CEF 调试端口后本机新增的监听面与其边界。
- [ ] macOS/Windows 分别记录实测结果与待测项；没有可用 Windows 环境时保留明确的平台验证关卡，不能声称跨平台通过。

**决策关卡：** 若 CEF 调试接入无法提供上述证据，或 Electrobun 在目标平台不可用，则回退到 Electron 桌面壳（主进程运行其内置 Node）加 Bun Host 的方案。回退必须作为明确结论连同证据写入本工单，并列出受影响设计，不得静默替换或含糊通过。

**执行纪律：** 长运行的 GUI 进程必须把 stdout／stderr 写向日志文件，并带看门狗强制退出。把长运行进程的输出管道给 `tail`／`grep` 会因缓冲而全程看不到输出，叠加桌面壳入口未捕获异常导致的进程不退出，会造成命令永久阻塞。macOS 没有 `timeout` 命令。

**验证方式：** 端到端驱动两个可见页面，断言实际 DOM 变化、独立存储和错误证据，并记录桌面壳与渲染器的实际组合。技术失败先修订方案，不直接进入产品集成。
