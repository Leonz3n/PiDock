# 20 — 渲染层基线（React／Tailwind／TanStack 复原现有草稿）

**What to build:** 把已终审的静态界面草稿按确认的栈复原为可运行的渲染层基线：同一批页面、同一 A 对话优先布局、与现有草稿逐页可对比的视觉结果，使用 React、Tailwind CSS 与 TanStack。该产物不是抛弃式原型，后续工单在此基础上继续演进。

**Blocked by:** None — 可与 01 并行推进；不依赖桌面壳选型结果。

**Status:** ready-for-agent

**Parent:** [首版规格](../spec.md)。视觉与交互基线见 [产品设计收口](../../../docs/product-design-closure.md) 和 [UI 审阅记录](../../../docs/ui-prototype-review.md)。

- [ ] 按规格「技术栈与运行时」建立渲染层工程：React、Tailwind CSS 与 TanStack；本工单范围内直接以开发服务器运行，不接入桌面壳与 Host。
- [ ] 复原既有草稿的全部页面与主要流程：项目页、环境与服务、Provider 与上下文、Token 用量、定时任务与模板、能力管理、远程访问、归档与清理、任务页与对话区、工具面板按需打开，以及 A 对话优先布局。
- [ ] 视觉与交互与现有静态草稿逐页对比并记录差异；保留既有的「不使用绿色作强调色、状态色或图表色」和 π 标记居中要求。差异必须是明确取舍，不能是未注意到的回退。
- [ ] 收口规则全部可演示：会话执行状态与审批、失败保留草稿、确认过期、跨项目「需要处理」、会话搜索与归档、按服务查看生效配置来源、归档任务清理清单预览。
- [ ] TanStack 覆盖面逐项记录：路由与搜索参数、数据获取与缓存、表格、虚拟滚动、表单与校验、低频客户端状态。每一项写明采用理由或不适用的理由；采用的部分要能指出它替代了哪些自研代码。
- [ ] 会话标签、长会话列表、Token 用量表格、执行记录等密集场景使用虚拟滚动或等价方案，并记录实际行数下的渲染表现；静态草稿只按固定数量演示，不能作为容量证据。
- [ ] 数据仍为内存模拟，不连接 Host、不发请求、不读写真实文件；与真实 Host 的接口边界在 02 定义，本工单不预设协议。
- [ ] 现有静态草稿（`prototypes/pidock-ui/`）保留为历史对照，不删除、不修改；本工单产物位于新的渲染层工程内。
- [ ] 组件选择优先社区活跃、可长期维护的方案，并记录所选组件方案与其许可证。

**验证方式：** 用开发服务器逐页对照现有草稿完成一次完整走查，记录视觉差异、TanStack 采用结论与密集场景实测数据；在 02 接入桌面壳前，本产物不声称已通过桌面环境、跨平台或真实数据验收。
