# 15 — 跨平台桌面包与首版验收

最终验收新增：16 能力管理、18 定时任务、19 远程访问；其依赖覆盖 17 Host。补验审批与重试、跨项目关注、归档恢复和清理、真实周期／时区／过期、移动端断线与去重，不能以 UI 模拟替代。

**What to build:** 用户能从 GitHub Release 获取 macOS ARM64 DMG 或 Windows x64 EXE，安装并运行首版桌面应用，在两个目标平台完成已定义的任务开发和本地验证工作流。

**Blocked by:** 07 — 真实对账单详情同步验证；14 — 生命周期；16 — 能力管理；18 — 定时任务；19 — 远程访问。

**Status:** ready-for-agent

**Parent:** [首版规格](../spec.md)。

- [ ] GitHub Actions 以版本标签触发，分别构建 macOS arm64 `.dmg` 与 Windows x64 `.exe` 安装包；不以压缩包、便携目录或其他架构替代。
- [ ] 两个平台的构建、架构检查、安装冒烟、签名／公证检查均通过后，才把同一版本的 DMG 与 EXE 上传到 GitHub Release；任一目标失败或缺失时不得标记完整发布。
- [ ] Release 资产名、应用内部版本、标签及 Release 标题一致并包含平台／架构；同时发布 SHA-256 校验值，保留提交、工作流和签名结果的可追溯信息。
- [ ] 正式 DMG 完成 macOS 代码签名与公证，正式 EXE 完成 Authenticode 签名；凭据仅由受保护的 GitHub Actions secrets／environment 提供，不进入仓库、普通日志或不可信 fork 工作流。
- [ ] 在干净目标系统验证安装、首次启动、重新打开、覆盖升级和卸载；升级和卸载不误删工作区、配置、会话及其他应保留数据。
- [ ] macOS/Windows 分别验证多仓库任务、配置编辑、进程树管理、PTY、浏览器和后台行为，以及 Provider 切换、上下文展示和持久 Token 统计。
- [ ] 两平台验证中文任务显示名称与英文数字任务目录分离、本机默认根目录持久化／单次覆盖、原路径恢复与追加，包含空格、盘符、反斜杠、权限和目录冲突；真实 Git 验证创建前获取最新远程基线、失败重试与逐仓库提交记录。
- [ ] 两平台分别验证 `@`、`$`、`/` 的补全、键盘行为、中文输入法及草稿恢复；含空格的路径和 Windows 盘符、反斜杠不会被误判为命令。
- [ ] 两平台检查不使用绿色的工作台视觉与 π 居中；验证工具按需打开/关闭及资源保留，左下角「+」的真实文件多选、取消和移除，以及右侧模型选择。完整 UI 规则以规格和 [审阅记录](../../../docs/ui-prototype-review.md) 为准。
- [ ] 明确记录实际操作系统及 CPU 架构；业务生成工具不支持的平台功能有具体原因和处理结果，不以未测当通过。
- [ ] 在可用平台重走真实对账单详情验收，记录业务环境前提和证据；依赖不可达时保留未完成状态。
- [ ] 首版验收覆盖规格中的全部用户可观察行为，区分已经完成、后续范围和外部前提。
- [ ] 提供最短上手流程：绑定仓库、导入配置、创建任务、启动验证、归档与清理。
- [ ] 验收结果、已知限制和恢复步骤随可运行产物交付；所有报告以实际运行证据为准。

- [ ] 两平台验证「+」后的权限浮层、键盘操作及窄栏显示；三档按会话保存，切换保留文字／图片附件草稿，重启恢复。以真实工具验证只读门禁、默认询问及拒绝／取消、自动执行仍遵循任务边界与共享模板确认、同任务写锁和在途请求权限记录。

- [ ] 两平台验证混合／纯目录任务创建、真实 pi 对链接的列举／搜索／读写、追加和恢复、链接名冲突及不可用目标；Windows symlink／junction 选择与权限需有证据。清理后原始文件保留，共享真实目标写协调按细化后的方案验收，不以 UI 演示替代。

**验证方式：** 从 GitHub Release 下载本次工作流生成的 DMG 与 EXE，在对应目标架构的干净系统安装并进入真实工作流，核对哈希、签名、内部版本、实际架构、应用重启与数据保留，再汇总前序各项结果。
