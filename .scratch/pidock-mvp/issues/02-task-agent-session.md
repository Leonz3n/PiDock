# 02 — 单仓库任务与 pi 会话

**What to build:** 用户在桌面中注册一个已有仓库，创建独立任务，与 pi 对话并修改任务代码，关闭后可恢复任务和会话。

**Blocked by:** 01 — 可见页面控制与桌面壳技术验证，明确桌面集成路线；20 — 渲染层基线，提供已复原的界面。

**Status:** ready-for-agent

**Parent:** [首版规格](../spec.md)。

- [ ] 桌面基础界面遵循规格中的视觉要求：不使用绿色作工作台强调色、状态色或图表色；π 标记居中。当前蓝灰原型的 A 对话优先布局作为实现基线，B/C 仅保留历史对照；不直接将原型代码提升为产品实现。
- [ ] 按规格「技术栈与运行时」接入桌面壳：Electrobun 固定版本并显式选择 Bun 主进程模式，自有界面使用系统 webview，任务页面使用 CEF 渲染器；Bun Host 承载 pi 运行时、受管执行与调度，界面与 Host 分离运行；不以 `prototypes/pidock-ui/` 的静态代码作为实现起点。
- [ ] 在 20 的渲染层基线上继续演进，而不是重新搭建界面；如因壳接入需要调整 20 的产物，将差异回写工单 20 的结论。
- [ ] Host 可用 `bun build --compile` 产出单文件二进制并可直接启动，目标机器不预装 Node 或 Bun 也能运行；记录实际 Bun 版本、Electrobun 版本与所选 pi 版本。
- [ ] 记录 pi 在 Bun 下的接入方式（SDK 进程内或独立子进程）与验证证据；因 pi 的 `engines` 只声明 Node，升级 pi 后必须重测该兼容性。
- [ ] 渲染层构建产物由桌面壳正确加载；界面与 Agent 仍共用同一任务操作入口，不因渲染层、主进程与 Host 分层而出现两套状态或两条写锁。
- [ ] 创建项目并绑定已有仓库，按规格「任务目录与远程基线」选择远程分支；创建前 fetch 并固定此次获取的提交，再建立独立分支/worktree；不依赖旧基线，不对主检出目录执行 pull/merge/reset。
- [ ] 中文显示名称、自动英文数字目录标识和可编辑任务分支分别保存；本机设置持久化默认任务根目录，新建可单次覆盖并预览实际路径。任务保存实际根目录，默认值变化或重开不会迁移已有任务；路径不可用和标识冲突明确处理。
- [ ] 获取失败保留表单及重试入口，不从旧引用创建；文件面板显示实际目录、远程基线与创建提交，主检出目录未提交工作保持原状。
- [ ] 显示任务名称、仓库、分支、准备状态及基本代码变化；异常信息关联到具体任务。
- [ ] 用户能配置 pi 支持的模型与本机凭据，发送消息，看到流式回复和工具结果，并中止当前执行。
- [ ] 从首个模型调用开始提供稳定调用身份，保留实际 Provider 配置、模型、usage 来源和事件；为后续多 Provider 和用量统计提供可恢复记录，不只保存渲染后的消息文本。
- [ ] pi 的代码工具使用当前任务的工作目录和允许访问的仓库范围；默认不能把写入目标回退到原检出目录。
- [ ] 接入真实 pi 工具前建立统一权限门禁，并接通 20 的权限入口：按会话保存只读／默认权限／自动执行，新会话默认权限；只读仅允许阅读分析，禁止写入、命令和浏览器操作；默认权限的 Agent 命令／浏览器操作先询问。自动执行仍受任务范围、共享模板确认、显式交付和任务写操作权约束。未接入门禁的工具不向 Agent 开放。
- [ ] 基础确认展示真实操作、目标、任务范围与内容版本，批准仅对本次请求生效且执行前复核，拒绝／取消不执行；保存请求权限和确认结果，重开不自动重放。权限变更只作用于后续请求；人工显式操作与 Agent 自主调用分别标识。04、06 复用该入口，09 扩展多会话与派生执行协调，17 扩展统一事件与跨项目关注。
- [ ] 用受控工具验证只读拒绝副作用、默认权限先询问且拒绝／取消后零执行、批准一次只执行一次、自动执行仍拒绝越界；包括重开后不重放，不以权限按钮的显示代替工具层验收。
- [ ] UI 与 Agent 共用任务操作入口；基础执行采用单会话，持有任务写操作权直到相关工具与子进程结束。
- [ ] 任务和会话分别持久化，重新打开任务恢复指定会话，不错误接续另一个任务最近的会话。
- [ ] 保留用户输入与发送记录的关联，持久格式可容纳后续结构化引用、技能来源和未发送草稿，不只依赖聊天界面的渲染文本恢复输入。
- [ ] 用临时仓库验证 Agent 修改只落入该任务；模型故障或取消不丢失已有消息与代码。

- [ ] pi 统一以任务文件夹作为启动 cwd，各 worktree 位于其下；数据与工具边界可由 03 扩展普通目录来源，不将项目固化为单个 Git 仓库。

**验证方式：** 完整演示创建任务、一次有文件修改的 pi 对话、中止和重开恢复，在 Electrobun ＋ Bun 主进程与 20 的渲染层上完成同一演示并记录实际运行时与壳版本；模型外的关键行为使用可重复执行的测试替身验证，另记录实际模型联通结果。
