## Problem Statement

开发者同时处理多个任务，每个任务横跨若干 Git 仓库。当前工具添加仓库后没有统一准备独立代码工作副本、环境配置和本地服务，重叠仓库容易互相干扰。已有命令行工具可以组织 worktree，但配置依旧需要手写，Agent 经常要等代码推送、合并和部署后才能验证。

实际项目已经提供默认配置和环境变量入口。缺少的是一个可图形化管理、能被 Agent 使用的任务运行环境，以及可由用户和 Agent 共同操作的浏览器验证入口。

## Solution

提供基于 pi AgentSession 的 macOS/Windows 桌面工作台。项目保存仓库、普通目录、服务和按环境组织的共享模板；任务按需准备 Git 独立 worktree 和普通目录软链接，并拥有运行资源、Agent 会话及浏览器状态。普通目录的文件保持共享，不承诺任务间隔离。

用户选择任务所需仓库、普通目录和要在本地启动的服务，应用准备代码、依赖和环境变量。业务服务继续读取仓库默认配置。用户与 Agent 通过同一套操作启动服务、查看日志、检查依赖和控制内置浏览器。修改后的代码可在本地完成验证，再进入代码交付。

桌面应用可保存多个 Provider 配置，在同一会话内切换 Provider 和模型。对话展示当前模型、上下文占用及压缩状态；Token 用量按实际模型调用持久记录，支持从会话查看明细，以及跨任务、项目、Provider 和时间范围汇总。

对话输入支持熟悉的符号入口：`@` 搜索并引用任务文件/上下文，`$` 选择并调用技能，`/` 打开命令菜单；通过搜索补全、键盘操作和可见引用标记完成输入。

桌面主机可按需启用远程访问入口，允许已配对手机查看项目、任务、会话和运行状态，并进行受限的对话与轻量管理。首选 Tailscale 私有访问，同时保留自建 PiDock Gateway；Funnel 仅作为实验性公网入口。

新建任务时可选择普通任务或定时任务。定时任务保存一次性时间或周期规则、Provider、模型、会话权限和提示词；每次触发在该任务的固定工作区内新建 Agent 会话，不复用上一次执行的对话上下文，历史会话可查看并继续对话。

首个真实业务验收采用 SaaS 订阅消费流水中的对账单详情同步查询，使用用户指定的前端、invoice、shipment 和 apis 仓库。详情查询经过本地 BFF、本地 invoice 及本地 shipment；普通账单列表仍使用旧 REST，不可代替该验收。协议仓库提供生成代码，不作为服务启动。远程依赖仍使用选定环境；异步 worker 与远程回调的完整验证安排在后续阶段。

## User Stories

1. 作为开发者，我希望注册已有本地仓库，以便沿用现有代码和认证配置。
2. 作为开发者，我希望一个项目同时包含多个仓库、普通目录和服务，以便描述完整业务系统。
3. 作为开发者，我希望为任务选择部分仓库和普通目录，也可仅选普通目录，以便只准备当前工作所需资源。
4. 作为开发者，我希望任务进行中追加仓库时也创建独立 worktree，以便扩大任务范围时继续隔离。
5. 作为开发者，我希望同一仓库参与两个任务时拥有独立分支和目录，以便并行修改。
6. 作为开发者，我希望按仓库选择基准分支，以便适配不同代码交付节奏。
7. 作为开发者，我希望重新打开任务后继续使用原有代码，以便不中断长期工作。
8. 作为开发者，我希望看到部分准备失败的具体资源和恢复入口，以便继续工作而不丢失已准备内容。
9. 作为开发者，我希望图形化维护服务启动方式，以便无需重复编写启动命令。
10. 作为开发者，我希望按环境维护变量和远程地址，以便快速选择开发或测试环境。
11. 作为开发者，我希望复用仓库默认配置，以便业务配置仍由业务代码维护。
12. 作为开发者，我希望将凭据和本机路径单独保存，以便共享模板可以提交和复用。

14. 作为开发者，我希望查看每个生效变量的来源，以便解释服务连接到哪个环境。
15. 作为开发者，我希望 Agent 自动调整任务端口和本地地址，以便避免手动改配置。
16. 作为开发者，我希望 Agent 修改共享模板时先展示差异，以便控制对其他任务的影响。
17. 作为开发者，我希望已有任务保留采用的模板版本，以便模板更新不会改变正在验证的环境。
18. 作为开发者，我希望显式更新任务模板并看到需要重启的服务，以便有意识地切换运行配置。
19. 作为开发者，我希望选择哪些服务本地运行、哪些使用远程，以便控制资源占用。

## Implementation Decisions

### 已确认的产品约束

- 仓库与服务分别建模，一个仓库可以提供多个服务，也可以只提供代码或生成产物。
- 任务生命周期独立于 Agent 会话；同任务会话共享代码和运行环境。
- 每个任务/仓库关联拥有独立 worktree 和分支。原检出目录的未提交修改不隐式进入新任务。
- 共享模板描述启动方式、环境变量和依赖声明；本机私有值分开保存，业务默认配置继续从任务代码读取。
- Agent 可以生成导入草案并调整任务配置；对共享模板的修改需要展示差异并确认。
- 同一任务同时只有一个会话执行有副作用的工作，其他会话保留受限的阅读分析能力；不同任务可以并行，包括属于不同项目的任务及其 Agent 会话。执行权按任务协调，不设项目级或全局单会话限制；共享普通目录不因任务不同就获得文件隔离，针对重叠真实路径的跨任务写协调仍需细化；切换当前项目／任务只改变可见界面，不暂停其他项目中的 Agent 执行或本地服务。
- 任务归档停止服务并保留持久状态，清理是独立动作。应用关闭窗口进入后台，明确退出则停止所属执行资源。
- 首版复用环境数据设施，通过业务已有变量选择测试资源；不自动创建隔离数据库或消息设施。
- 内置浏览器按任务独立持久化登录状态；首次登录由用户完成。
- 桌面端支持多个 Provider 配置及会话内切换，对话展示上下文用量等状态，并可统计 Token 消耗。
- 对话输入支持 @、$、/ 等常用符号入口和相应的搜索补全交互，沿用用户已有的 Agent 操作习惯。

### 任务目录与远程基线

2026-09-20 用户确认新建任务／追加仓库界面，包括中文任务名称、独立目录标识、可配置任务根目录，以及创建前获取远程最新基线。以下为正式设计要求，真实磁盘和 Git 行为仍待实现验收。

- 任务显示名称支持中文，与目录标识、分支名分别保存。应用自动生成 `task-<8 位英文数字标识>` 任务文件夹，默认任务分支为 `task/<同一短标识>`，分支可独立修改；修改显示名称或分支不迁移目录。短标识需检查冲突，不能作为不经校验的唯一性保证，不接管或覆盖已有未知目录。
- 「本机设置」保存默认任务根目录，不写入项目共享模板；新建表单带入默认值，允许仅为本次任务修改。创建前实时预览目标路径，结构为 `<任务根目录>/<自动任务目录>/<仓库目录>`。每个任务保存实际采用的根目录及路径；更改默认值只影响后续新任务，重开、恢复和追加仓库沿用已有任务路径。
- 正式创建前校验完整路径、权限、目录占用及跨平台命名限制；路径不可用时明确提示，不静默换到其他根目录。不以中文显示名称构造任务文件夹；用户选择的上级路径及既有仓库名称另按实际路径规则处理。
- 每仓库分别选择明确的远程和基线分支，界面例如 `origin/main`、`upstream/release/v2`。主操作为「获取最新基线并创建／添加」：先 fetch 所选远程分支，确认此次获取成功并解析该分支的完整提交身份，再从固定的该提交创建独立任务分支和 worktree。不能仅读取缓存的远程跟踪引用或本地基线分支；远程分支消失时不能使用遗留引用继续。
- “最新”指此次创建准备阶段 fetch 获取的所选分支头部提交，不保证远程在之后不再推进，也不要求各仓库在同一时刻更新。记录远程、分支、实际创建提交，文件视图可查看来源；不对原检出目录执行 pull、merge 或 reset，原分支、未提交工作和其他任务保持原状。
- 本次所选仓库的远程获取全部成功后才开始创建工作副本。认证、网络或分支不可用时标明具体仓库与原因，保留表单及重试入口，不静默使用旧基线。重试在新的准备阶段重新获取所选分支并固定提交；后续 worktree 创建阶段若部分失败，仍按逐仓库结果保留已创建资源、提供恢复入口，不覆盖用户修改。
- 追加仓库只获取并创建新增仓库，使用当前任务的根目录、任务文件夹及分支命名；已有工作副本、创建基线和运行状态不自动更新。同仓库并发获取／创建需要协调，避免另一任务更新远程引用后改变已固定的创建提交。

### 混合目录与任务软链接

2026-09-21 用户确认此组设计：一个项目可以同时包含 Git 仓库和普通目录；任务统一从任务文件夹启动，普通目录通过软链接接入。取代项目级 Git／普通目录二选一和直接向 pi 传入多个普通路径的历史方案。此确认不表示真实链接操作或 pi 兼容性已经验收。

- 项目按条目维护多个仓库和普通目录，普通目录具有稳定身份、显示名称和原始完整路径。任务可混选、只选 Git 或只选普通目录，至少选择一项；项目新增条目不自动加入已有任务，任务可以显式追加。
- 所有任务均在配置的根目录下创建 `task-<8 位英文数字标识>`，pi 以该任务文件夹为统一启动工作目录，不依赖额外目录参数。Git worktree 置于仓库子目录；普通目录以 `dir-<目录 ID 前 8 位英文数字>` 软链接加入同级位置。显示名称与路径分开，中文名称不用于生成任务／链接名，不重命名原始目标。生成名称需校验冲突，不覆盖已有入口。
- 仅选普通目录时仍校验任务根目录并预览任务文件夹，不要求 Git 分支、远程获取或环境，不自动初始化 Git。混选时仅获取本次新增仓库，全部获取成功后再准备 worktree 和链接；不因普通目录存在而使用旧基线。
- 创建预览同时显示任务入口、每个 worktree 路径、每个链接路径及其原始目标，单次根目录覆盖实时更新预览。任务保存根目录、标识、目录来源快照和链接名；重开、恢复和追加沿用既有路径，不迁移已有资源或更新已有 Git 基线。
- 文件／终端展示统一 pi 工作目录和当前选定入口，普通目录显示链接与原始目标，并明确「修改会影响原目录，文件未隔离」。Git 差异和交付仅适用于仓库；普通目录不显示虚假的 Git 状态。文件及 `@` 引用记录链接内路径与来源身份／目标，不因同名目录混淆来源。
- 归档保留链接。清理仅移除身份可确认的任务内链接，保留原始目标及其文件，禁止沿链接递归删除目标；Git worktree 仍独立审阅未交付内容。链接失效或被替换时明确报告，不静默改指其他目录。
- 运行时待验证／细化：pi 列举、搜索、读取和写入链接的能力；Windows symlink／junction 的选择及创建权限；目标存在性、链接冲突、嵌套／循环目录、部分创建失败恢复。来源授权按解析后的真实路径检查，任务内链接不能自动授权任意外部目标；共享目录跨项目／任务写协调及外部程序并发边界仍需设计，任务 ID 锁不能证明这些文件隔离。保持非重叠资源的跨任务并行，不将未定协调协议标为已确认。

### 工作台工具面板

- 新任务默认仅展示对话，运行概览、内置 Web 浏览器、文件浏览器、终端和日志等工具按需打开，不预先占用工具区空间或创建对应运行资源。

### 会话权限选择

2026-09-21 用户确认输入框旁的权限选择设计。以下为产品要求；前端选择与只读模拟不代表真实权限执行、审批或系统隔离已经实现。

- 输入框底部「+」右侧常驻显示当前权限，点击打开贴近入口的小浮层，展示档位、可做的操作、询问规则和当前选择；模型与推理入口仍位于右侧。支持键盘选择、Esc／点击外部关闭，窄对话栏可换行且入口可用。

| 档位 | 操作范围与询问规则 |
| --- | --- |
| 只读 | 阅读任务文件、分析和回答问题；不修改文件，不执行命令或浏览器操作 |
| 默认权限 | 允许任务内文件读写；Agent 执行命令或操作浏览器前询问 |
| 自动执行 | 允许任务内文件读写、命令与浏览器操作，无需逐次询问 |

- 各档位均遵循已定义的任务访问范围、共享模板变更确认、显式 Git 交付及同任务写操作协调。自动执行不扩大为整机任意访问，也不绕过任务写锁；只读权限和因另一会话持锁而暂时只能阅读的状态分别记录和展示。
- 权限按任务／Session 独立保存，新会话使用「默认权限」，代码审查示例初始为「只读」；实际权限不由会话名称或标签位置决定。调整后更新入口与只读标识，保留文字、附件草稿、模型及历史；不改动其他会话或项目。
- 选择用于后续请求，已启动的 Subagent 保留启动时权限，不追溯扩大或撤销在途执行。记录每次请求实际采用的权限及归属，重启／恢复保留会话选择，不自动重放请求或工具操作。此条确定权限生效原则，不代表 Subagent 列表与侧栏的整组 UI 已确认。
- 正式工具入口执行权限校验与审批，不能仅隐藏按钮或依赖会话提示词；只读不能通过终端、浏览器变更或派生执行绕过。人工显式按钮操作与 Agent 自主调用需区分，现有只读限制与写操作协调保持一致。默认权限的询问需展示实际操作及任务范围，拒绝或取消后不执行，保留可解释状态。
- 运行时接入仍需验证 pi 可用机制、在途请求边界、派生权限传递、审批等待／拒绝／取消及恢复；工作区工具范围不是操作系统级 shell 沙箱，不作未经验证的隔离保证。

### 对话输入、引用与命令

输入框底部左侧使用一个「+」文件附件入口，点击打开系统文件选择器，可多选、取消，已选文件显示名称并可移除；其右侧常驻会话权限选择；模型选择位于底部右侧、发送按钮之前。不常驻显示 `@`、`$`、`/` 按钮，但输入这些符号时保留搜索和补全。

文件选择可以通过桌面系统对话框实现；仅处理用户明确选中的文件，不因为选择仓库外文件而扩大任务工具可访问的目录。正式接入发送时需显示支持的类型、内容范围及大小限制，不支持的附件明确提示；与任务文件引用分别保留来源。

符号的首版映射如下。这是 PiDock 的交互定义，不承诺复制其他产品的所有命令名称或行为。

| 入口 | 首版行为 |
| --- | --- |
| @ | 在当前任务所选仓库和普通目录搜索文件/目录，支持从文件视图插入代码片段；候选显示来源、相对路径和类型 |
| $ | 按技能名和描述搜索，展示来源并调用选定技能，可附带自然语言参数；兼容 pi 的显式技能入口 |
| / | 消息开头打开分类命令菜单，包含应用操作、提示模板及可接入的扩展命令，支持参数提示 |

- 候选列表提供方向键选择、Tab/Enter 确认、Esc 关闭；列表打开时 Enter 优先确认候选，不同时发送消息。普通编辑使用 Enter 发送、Shift+Enter 换行，支持后续快捷键设置；中文输入法组合输入期间 Enter 不触发提交或命令。
- 引用以可删除/预览的标记呈现，保留稳定来源和任务归属，不能仅保存一个可能重名的字符串。多仓库同路径文件分别展示，技能重名时显示全局/项目/仓库来源并让用户选择具体项。
- 文件引用在发送时解析到当前任务的实际工作副本或已关联普通目录；记录来源、内容范围及适用的版本信息，普通目录不虚构 Git 版本。文件不存在、越出可访问范围或技能已失效时提示重新选择，不能静默退回原检出目录、另一任务或其他同名项。
- 默认搜索尊重仓库忽略规则并限制结果数量；明确选择的忽略文件单独处理。目录引用提供路径和有界目录信息，不自动把整棵目录的全部内容塞进上下文。大文件、二进制或过长片段明确显示实际提供范围，不静默截断后假装全文已送达。
- 在发送前可检查引用和技能将引入的上下文；发送后的来源记录用于解释历史输入。引用预估大小不能当作供应商实报 Token 用量。
- 全局及项目/仓库技能由已启用的资源来源加载，支持常见技能目录和用户显式添加的来源；多仓库聚合由桌面应用完成，不能假设 pi 会自动遍历任务中的所有相邻 worktree。
- `$技能名` 是桌面技能选择语法，可在自然语言中插入；将选定来源的技能内容按需交给 Agent，并保留其资源相对路径。也支持 `/skill:技能名` 入口；混合多个引用/技能时只展开一次，不通过盲目字符串替换改变正文。
- 初始应用命令包括 `/new`、`/model`、`/compact`、`/skills`、`/session`、`/usage`、`/help`。`/new` 在当前任务中新建会话并保留旧会话和 worktree；`/model` 打开 Provider/模型选择；`/session` 展示当前会话信息；`/usage` 展示用量。菜单只展示已支持的入口，不将 pi TUI 的所有命令当作 SDK 原生能力。
- 应用命令通过既有会话、Provider 和统计操作执行，不依赖模型理解文本后代为操作。提示模板按原有机制展开，扩展命令按注册能力接入；显示各自来源、作用域与参数，重名入口明确消歧。
- 忙碌时遵循各操作已有规则：切换模型、新建会话或压缩需要合适的空闲边界；无法排队的扩展显示不可用或要求执行结束。普通新消息可按明确选择进入 steer/follow-up，不能将不支持排队的命令直接交给 prompt 而绕过任务协调。
- 符号仅在对应编辑上下文中触发补全；邮箱、URL、路径、代码块、行内代码、普通 `$HOME` 和转义文本保留原意。只有已选择或明确解析为可用入口的标记才执行；未知命令提示纠正，不自动当作 shell 执行。
- 草稿保存文字与结构化引用/技能选择；重新打开时校验来源。技能或引用内容的使用仍遵循任务访问范围、只读会话限制及共享模板确认规则，快捷入口不增加权限。

### Provider、上下文与用量行为

以下细化规则用于实现新增需求，范围限于本应用的模型调用记录。

- Provider 配置具有稳定身份，保存显示名称、协议类型、服务地址、认证引用及模型信息。同一供应商的不同配置可并存；模型信息包含能力和窗口上限，未知值不伪造。
- 协议类型明确支持 `Anthropic Messages`、`OpenAI Responses`、`OpenAI Chat Completions` 三种，独立于 Provider 显示名称和服务地址保存；新增可选择，编辑回显原选择。运行时按所选协议适配请求、流式响应、工具调用及 usage，不将两种 OpenAI 协议合并为一个“兼容”选项。
- 一个 Provider 配置可维护多个模型，图形化添加、编辑和移除；模型共享该 Provider 的连接与认证，每个模型保留自身标识、窗口及能力。对话选择器按 Provider 分组列出模型，会话保存 Provider 身份和具体模型的组合；同 Provider 内切换模型不影响其他会话。移除正在被会话引用的模型时保留历史归属并提示重新选择，不静默替换。
- 添加和编辑 Provider 的模型列表提供「同步模型列表」按钮，依据当前连接获取模型 ID 候选。同步更新候选列表，保留已配置模型及其能力设置；不自动将返回的所有模型加入配置。模型 ID 始终可直接填写，同步后也可展开下拉列表选择或输入筛选，支持键盘选择；手填 ID 无需出现在候选中，同一 Provider 内不允许重复 ID。
- 显示名称默认填入并跟随模型 ID；用户手动修改后保留自定义名称，不随 ID 变更或同步覆盖。清空显示名称后恢复默认跟随；保存与再次编辑保留名称及其跟随状态。
- 模型候选属于当前 Provider 连接。服务地址、协议或认证改变后需要重新同步，不能将旧连接结果视为当前可用模型。正式接入须区分同步中、成功、空列表、失败和服务不支持模型发现；失败或不支持时仍可手动配置。模型 ID 列表不等于窗口、图片或推理能力目录，不从同步成功推断这些能力已验证。当前 UI 同步只使用示例数据，实际发现接口按协议与服务另行验证。
- 每个模型采用可展开的设置卡片，分别维护模型 ID、显示名称、上下文长度 `contextWindow`、最大输出 Tokens `maxTokens` 和图片输入能力 `input`（文本或文本+图片）。数值按实际服务限制填写；上下文长度不是独立的单次输入上限。图片能力关闭时不把图片附件直接发给模型，应提示移除图片或切换支持图片的模型，既有图片历史按能力适配规则处理。
- Provider 凭据归本机私有配置，不进入项目共享模板或对话。编辑、停用配置不改写历史调用的 Provider、模型及配置版本归属。
- 添加/编辑每个模型时可填写上下文窗口，单位 Tokens，保存为正整数并映射至 pi 模型的 `contextWindow`；与最大输出 Tokens 分开。已知模型可使用有来源的目录值，自定义模型采用默认值时明确其尚需核对，不能假装已验证。会话按当前模型窗口显示占比；编辑窗口在安全执行边界生效，缩小窗口时重新评估压缩与已有上下文。填入更大值不会扩大供应商/网关的真实限制。接口依据见 pi 能力核对。
- 会话内选择 Provider 和模型，保留任务、历史、未发送草稿及工具结果，不隐式修改全局默认或其他会话。记录切换事件，历史响应显示其实际 Provider/模型。
- 对话中的模型、推理档位与上下文详情使用贴近各自入口的小浮层。模型入口仍位于输入框右侧；候选按 Provider 分组，可搜索 Provider、模型 ID 与显示名称，展示上下文容量、图片能力和当前选择。支持方向键选择、Enter 确认、Esc 或点击外部关闭，并提供模型管理入口。
- 当前回合、工具执行或压缩进行中，切换操作等待其结束；用户也可先停止当前执行再切换。切换前检查认证和模型能力，不在一个进行中的请求或工具循环中混用配置。
- 当前会话上下文占用超过目标模型的上下文上限时，禁止切换。选择器将该模型置灰，显示当前占用和目标上限，例如「当前上下文 24.8k，超过该模型 16k 上限」；对话浮层、Provider 页选择器、命令及其他切换入口使用同一校验，真正执行切换前再次读取当前状态。拒绝时保留原模型、历史和草稿，不先切换再压缩，也不因点击目标模型而自动截断或压缩历史。用户可先在当前模型下压缩，待占用更新且不超限后重新选择，或在新会话中选择该模型。
- 超限比较使用未格式化的 Tokens 数值；严格大于上限时阻止，相等时不因本条规则阻止，但仍须满足认证、内容能力及发送请求的预算要求。上下文占用待更新或目标窗口未知时暂不允许切换，明确说明原因；估算值标明估算，正式接入需验证运行时的计算口径与目标模型适配。
- 新模型不支持历史内容时，提供明确的不兼容状态并要求调整；不静默丢弃历史或声称跨 Provider 原生思维状态能够完整迁移。
- 对话状态区显示 Provider、模型、可用时的思考级别、当前上下文 Tokens/窗口上限/占比，以及空闲、生成、工具执行、压缩和重试状态。预估剩余量需标识为估算，不能保证等于下一请求可容纳的输入。
- 上下文占用采用 pi 当前有效上下文的信息，考虑工具结果、系统上下文和压缩，而非简单累加可见聊天文字。切换模型后按新窗口重新评估；压缩后尚无可靠值时显示待更新。
- 输入框下方直接显示上下文占用、当前模型窗口、百分比及估算标记；点击打开详情浮层，展示当前 Provider/模型、占用与累计消耗的区别，并提供压缩入口。压缩降低上下文占用，不减少累计 Token；未知不显示为零，可靠值尚未更新时不沿用旧精确比例。
- Token 明细区分输入、输出、缓存读取、缓存写入；供应商报告 reasoning 时可以展开显示，但它若已包含于 output 就不再次相加。各 Provider 归一化字段的含义需核对，不把缓存字段或 provider total 重复计入。
- 累计统计以实际调用记录为依据，不以当前可见上下文、消息长度或重复读取的会话总数作为新增量。压缩、分支摘要及模型型工具调用在有可用 usage 时也归档，保留调用类型。
- 每次执行有稳定身份，记录原始任务/会话、Provider 配置与版本、请求模型及可用时的实际响应模型、时间、结束原因、usage 来源和报告完整性。流式增量及最终汇总更新同一记录，不能重复相加。
- 重试是新的实际调用尝试，有报告用量时分别计入；取消/失败也可能消耗 Tokens，记录已知用量。上游未返回 usage 或应用中断造成未知时标记缺失，不能从零填充值推断免费。
- 恢复、压缩、分支/克隆或重新导入历史不生成新的消耗；继承记录保留来源身份，跨会话汇总只计原调用一次。界面可展示继承历史，但费用归属仍是原任务/会话的实际调用。
- 提供单次调用、会话累计及时间范围内按项目/任务/会话/Provider/模型的汇总。持久记录可重建统计，重启后不归零；归档任务保留统计，清理对话时明确是否同时清理用量。
- 上下文占用和 Token 消耗分开显示；压缩降低前者，不冲减后者。此统计不是供应商账单、余额或速率配额查询，也不包括本应用未观测到的外部调用。

### 推理能力配置与会话档位

2026-09-20 用户先后确认 Provider 添加/编辑及对话中的模型、推理档位与上下文交互。下述界面作为设计基线；协议映射与运行时生效行为另做集成验证。

- 模型配置与会话选择分层。配置支持「跟随模型目录」「不支持推理」「自定义可用档位」；已知模型优先使用目录与 pi 解析后的能力，自定义未知模型不推断为支持全部档位。
- 自定义档位从 pi 支持的 `off/minimal/low/medium/high/xhigh/max` 中明确选择子集，可跳级；`off` 也受模型能力约束。只支持单一档位的模型显示固定能力，不提供无意义的多选切换。
- 指定该模型的默认档位。高级设置才暴露到服务参数值的映射；默认映射、显式字符串和不支持的 null 区分处理，未勾选档位在生成配置时显式设为 null，不能靠省略禁用。
- 对话输入区仅提供当前模型实际可用的推理档位；偏好按会话及 Provider/模型组合保存。切换时可恢复此前仍有效的选择，否则使用明确的模型默认并显示调整信息；已有偏好失效不静默升级推理强度，界面展示最终生效值。
- 推理档位浮层标识当前选择与模型默认值，并可进入当前 Provider 的模型设置。跟随目录但尚未获取能力时说明状态，不虚构档位；不支持推理时隐藏入口，单一可用档位显示固定值。
- 推理选项遵循模型切换的执行边界。档位不是跨供应商统一的思考 Token 数、速度或费用承诺；需要数字预算、adaptive 等额外控制时，通过已核实的适配器放入高级设置，不将任意自定义字符串伪装成通用能力。

### 远程访问与设备配对

2026-09-21 用户确认保留 Tailscale 私有访问和自建 PiDock Gateway，并将 Funnel 作为实验入口；同时确认桌面生成二维码、手机扫码打开链接的配对流程。当前只有 UI 模拟和技术调研，不表示真实网络、认证或移动端已经运行验证。

- 推荐首版先实现 Tailscale Serve：PiDock Host 只监听 `127.0.0.1`，Serve 在 tailnet 内提供 HTTPS；手机必须加入同一 tailnet，并通过 Tailscale Grants 限制可访问用户。PiDock 仍执行设备授权和领域权限，不能仅凭 tailnet 可达就授予操作权。
- 保留自建 PiDock Gateway：Gateway 提供公网 HTTPS/WSS，桌面主机主动建立并维持出站连接，不要求家庭或办公网络开放入站端口。手机只调用 Gateway 暴露的 PiDock Web/API，Gateway 再将已认证、已授权的请求路由到指定在线主机；不转发任意 TCP，不暴露 pi stdin/stdout JSONL RPC、终端或本机文件系统。
- 自建 Gateway 至少负责 TLS 与域名接入、用户登录、一次性配对交换、设备凭据签发与轮换、主机在线状态与连接路由、断线重连、请求限流、权限校验、设备撤销和安全审计。服务端密钥、数据库备份、升级、监控和滥用防护属于部署者运维责任；不能把 DERP 当作 PiDock 业务 Gateway。
- Funnel 无需手机安装 Tailscale，但地址对互联网公开，只作为实验入口。启用时必须沿用完整的 PiDock 登录、设备授权、限流与审计，不将 Funnel 自身的可达性视为身份认证。
- 桌面为当前入口生成配对链接和二维码。二维码只携带高熵、短时、单次配对凭据，建议有效期 10 分钟；凭据放在 URL fragment 中，避免随常规 HTTP 请求和代理日志发送。手机扫码自动打开链接，在交换凭据并登录后等待桌面确认设备名称与权限；凭据在使用、过期或桌面刷新二维码后立即失效。
- 成功配对后为每台远程设备签发独立、可轮换、可撤销的设备凭据，不复用二维码凭据。设备默认只允许查看项目、任务、运行状态以及查看／发送对话；暂停、归档、启停服务等轻量管理再次确认，文件／差异默认关闭，远程终端和高风险配置变更默认关闭或要求本机确认。
- 远程访问复用既有任务、会话和执行协调，不创建绕过桌面权限的新控制面。会话权限、任务写锁、共享模板确认、显式交付和浏览器接管规则不因远程访问放宽。
- 首版不承诺主机离线时继续查看完整历史或排队执行命令；如后续引入服务端数据缓存，需单独定义加密、保留期、删除与多租户隔离。

### 最终产品设计收口

2026-09-21 用户要求按最终审查建议推进，采用 [产品设计收口](../../docs/product-design-closure.md) 中的执行／审批／重试、跨项目关注、会话导航、配置来源与清理规则。确认到下一计划时刻或 24 小时较早者过期；恢复归档任务不自动恢复调度；模板获取远程新记录但不自动合并工作区。真实计时、持久化和外部工具另行验收。

### 定时任务与执行记录

2026-09-21 用户确认本轮定时任务与内置模板设计。新建入口、类型标记、固定任务工作区内的独立执行会话、可继续对话的历史、提示词内的结果处理，以及五个含完整默认提示词的可编辑模板均已确认。模板需点击「使用模板」后填入周期和提示词。以下为首版设计基线，默认使用需要时等待确认的会话权限，离线不补跑、上次仍运行时跳过；真实调度与恢复行为仍需实现和验收。

- 新建任务时明确选择普通任务或定时任务，进行中任务列表始终标识类型。定时任务保存稳定身份、所属项目、固定任务工作区、Provider 配置与模型、时区、一次性时间或周期规则、新会话权限、初始提示词和启停状态。模型必须保存 Provider 配置身份与模型 ID 的组合，不能只保存可能重名的显示名称。
- 结果如何汇总、保存、通知或发送属于提示词内容，不另设一套定时任务交付配置。Agent 只能使用该会话已启用的工具并遵循会话权限、外部操作确认及既有执行规则；执行记录保留实际工具结果和失败原因。
- 每次触发在该定时任务中创建新的 Agent 会话，选择固定的 Provider 与模型并发送提示词。不同执行不继承消息、上下文或未发送草稿，但共享该任务的工作区、代码和运行环境；任何写操作继续受同任务协调约束。
- 定时执行是独立记录，关联定时任务版本、预定时间、实际开始与结束时间、创建的会话、结束状态及错误。历史会话保留在任务会话栏中，可直接打开并继续对话；后续消息属于原执行会话，不改变下一次触发的新会话。修改定时设置只影响后续触发，历史执行仍显示当时实际采用的模型、权限和提示词版本。
- 定时会话沿用普通任务的目录准备、权限、任务写锁、共享模板确认、Provider 认证、Token 用量、后台运行、归档和清理规则。只读或默认权限可能停在等待确认状态；选择自动执行也不能扩大项目范围或绕过共享模板和显式交付规则。
- 同一定时任务的上一次执行仍未结束时，首版跳过本次触发并记录原因，不并发运行也不排成长队。不同定时任务仍按其目标任务范围参与既有写操作协调。
- 首版调度器由 PiDock Host 承载，仅在主机开机且 Host 运行时触发。离线期间错过的时间不补跑；恢复后计算下一个未来触发点并记录错过原因。系统休眠、时钟回拨、夏令时和应用重启不能造成同一预定时间重复执行。
- 项目被删除、Provider 停用、模型移除、凭据失效或规则无法解析时不静默改用其他值；该次执行标为失败或不创建会话，定时任务显示需要修复。一次性任务成功触发后自动停用，失败是否重试由用户明确操作。
- 支持暂停、恢复、立即运行和查看执行记录。立即运行同样在当前定时任务中创建独立执行与新会话，但不改变下次计划时间；删除定时任务不删除已有历史会话和用量记录。
- 周期规则至少支持每日、每周和五段 Cron，并保存 IANA 时区。界面显示可读规则和下一次触发时间；Cron 解析、跨平台唤醒能力及本机通知必须用真实时钟测试，不能由页面倒计时替代。

### 安装包与 GitHub Release

2026-09-21 用户确认首版通过 GitHub Actions 构建并随 GitHub Release 分发两个安装包。目标架构为 macOS `arm64` 与 Windows `x64`，不以 macOS x64 或 Windows arm64／ia32 产物替代。

- macOS 产物为可安装的 ARM64 `.dmg`，Windows 产物为可安装的 x64 `.exe`；仅有压缩包、便携目录、其他架构产物或未标明架构的文件不满足发布要求。
- 版本标签触发 GitHub Actions 的双平台构建与发布流程。两个平台独立构建和校验，只有同一版本的 DMG 与 EXE 均成功时才发布完整 GitHub Release；任一目标失败、缺失或架构不符时不得把该版本标记为完整发布。
- Release 资产名称包含应用版本、平台与架构，并提供可核对的 SHA-256 校验值。应用内版本、安装包版本、标签和 Release 标题保持一致。
- 正式 Release 的 DMG 完成 macOS 代码签名与公证，EXE 完成 Windows Authenticode 签名；签名凭据只通过 GitHub Actions 受保护的 secrets／environment 使用，不写入仓库或构建日志。来自不可信分支或 fork 的工作流不获得发布凭据。
- 两个平台均在干净目标系统上验证安装、首次启动、重新打开、覆盖升级与卸载；安装和升级不得清除用户工作区、配置或会话数据。GitHub Actions 构建成功不能替代目标机器上的安装验收。
- 发布流程保留工作流运行、提交、依赖锁定、产物哈希与签名／公证结果，使每个 Release 资产可追溯到唯一源码版本。是否自动生成草稿 Release 可由实现决定，但上传最终资产与公开发布必须在全部门禁通过之后发生。

### 建议实现边界

以下为实现建议，关键平台能力需要原型确认；不视为已经运行验证的事实。

- 采用 Electron 与 TypeScript；应用窗口承载产品界面，独立进程承载 pi 运行时和受管理执行。前端网页与本机能力通过受控接口连接。
- 桌面界面与 Agent 工具调用同一任务操作入口。任务标识由应用绑定，工具不能通过省略任务参数回退到另一个任务。
- 工作区管理负责 Git 对象及文件身份、跨仓库准备、局部失败和恢复；配置解析负责模板版本、变量绑定及可解释的生效结果；运行管理负责进程、端口、准备步骤和健康状态；浏览器管理负责任务页面及自动化；会话管理连接 pi 与这些能力。
- devtask 的工作区与恢复设计作为参考，是否直接复用其 Go 实现取决于跨平台和进程集成成本。首版接口不依赖其当前 symlink 布局。
- 环境变量按服务解析和传入子进程，不在桌面应用进程中切换全局环境。系统工具链所需环境与项目业务变量分别处理，避免上一任务变量进入下一任务。
- 共享环境值、本机私有值、任务覆盖依次参与解析；自动地址绑定在端口分配后完成。保留变量来源，引用缺失或存在冲突时提供可操作错误。业务框架内部读取优先级以实际代码为准。
- 变量引用使用明确声明，避免将配置值当 shell 表达式执行。使用环境变量可能还不足以覆盖的遗留字段，在导入时标为需要适配。
- 端口分配和进程启动之间可能出现竞争，运行管理在启动失败时重新解析受影响的地址或报告失败。运行中服务的端口不会被静默替换。
- 服务调用依赖与启动前置条件分开。双向调用的服务可以作为一组开始监听，再进行联通和业务检查。
- 每次运行保存模板版本、代码状态、准备产物、依赖绑定和实例标识。日志、浏览器证据与业务验证结果关联到该运行记录。
- 协议未修改时保留发布依赖；需要本地协议时，在任务中生成并显式绑定消费者，记录解析路径和生成版本。重新安装依赖或再次生成后检查绑定是否仍有效。
- 首个同步查询只启动实际需要的常驻服务。异步队列消费、调度器和远程回调分别验证，不能由主服务健康检查替代。
- 普通文件工具校验任务目录归属及已关联普通目录的真实目标范围；不能仅检查链接所在路径的文本前缀。工作区与工具作用域隔离不等于任意 shell 命令的操作系统沙箱；首版避免对后者作保证。人工终端接管与 Agent 写操作需要明确协调。
- 会话写锁覆盖整个有副作用的执行过程和派生工具；只读会话不能通过终端或浏览器变更操作绕过该限制。
- 退出时根据已记录的进程身份停止所属进程树，不通过端口或过期 PID 猜测归属。异常恢复先核验现存资源，再提供恢复/重启入口。
- 浏览器使用每任务独立持久会话，按任务和标签页绑定控制句柄。优先语义快照与定位操作，失败时按需补充截图、控制台和网络证据。
- 浏览器自动化首选评估 Playwright/CDP 与 WebContentsView 的组合；多会话发现、目标映射、弹窗、接管和重连必须实测，不能从普通 Electron 自动化支持直接推断可用。
- 保留浏览器登录时检查试点前端已知的 BFF 地址覆盖项，避免陈旧 localStorage 将请求引向旧实例；不通过清空全部站点数据解决该问题。

| 工具面板按需打开 | 初始工具区关闭，顶部或对话入口打开对应标签，可逐个关闭和收起；最后一个关闭后释放空间，不隐式停止服务、结束终端或清理浏览器状态 |
| 输入框与文件选择 | 左下角「+」调用真实系统文件选择器，支持多选、取消和移除；模型选择位于右侧；无常驻符号按钮但键入补全仍可用 |
| 中文名称与任务目录 | 中文名称正常显示，自动任务目录使用英文数字标识；名称／分支修改不改变路径，短标识碰撞和未知目录占用不造成覆盖 |
| 默认根目录与单次覆盖 | 本机设置持久化，新任务带入默认值并可单次修改，预览与实际创建一致；默认值变化不迁移已有任务，重开／追加沿用原路径；覆盖权限失败和两平台路径 |
| 创建前最新远程基线 | 本地 main 和远程跟踪引用均落后时，从本次 fetch 得到的所选远程分支提交创建；逐仓库记录完整提交，原检出目录未提交修改与其他任务不变 |
| 获取失败与重试 | 网络／认证失败或远程分支删除时，指出仓库、保留表单且不使用旧引用；全部获取成功后才建 worktree；重试重新获取，覆盖强推和多任务并发获取 |
| 混合与纯目录任务 | 一个项目可混选仓库与普通目录或仅选普通目录；均创建任务文件夹，pi cwd、链接／目标和预览一致；只选普通目录无需 Git 或环境 |
| 普通目录链接与清理 | 中文显示名与 ASCII 链接名分离；修改影响真实目标，追加／恢复保留身份，清理仅移除链接；失效／替换／循环链接不导致越界读写或目标删除 |
| 链接兼容性与共享写入 | 两平台以真实 pi 工具完成列举／搜索／读写；同一或重叠真实目标跨任务／项目时按后续协调方案验收，不以不同任务 ID 证明隔离 |
| 两任务共享两个仓库 | 写入任务一只改变其 worktree；任务二和原检出目录不变 |
| 任务追加仓库中途失败 | 已有工作可恢复，失败资源可识别，无未知目录被接管或删除 |
| 环境解析与启动 | UI 与 Agent 使用同一有效配置；子进程实际连接本任务服务 |
| 冲突端口与循环调用 | 报告或恢复冲突；双向依赖不会造成永远等待启动 |
| 本地协议修改 | 消费者实际解析本任务产物，版本不兼容时停止并解释；另一任务依赖不变 |
| 会话权限 | 「+」后选择只读／默认权限／自动执行；会话独立保存与恢复、草稿保留；真实工具门禁、默认询问及拒绝不执行、自动执行仍受任务范围与写锁约束、在途请求权限不被追溯改写 |
| 会话并发 | 同任务写操作不会重叠；只读工具不能绕过；同项目与跨项目的不同任务均正常并行；切换项目不暂停其他项目的 Agent／服务，回到原项目可继续查看其执行结果 |
| Provider 配置与切换 | 同供应商两套配置可独立使用；同会话切换后继续历史，仅后续调用改变 Provider，其他会话不变 |
| 忙碌与不兼容切换 | 进行中的调用/压缩不被中途替换；失效认证、窗口缩小或能力不匹配有明确处理结果 |
| 超限模型切换 | 24.8k 上下文不能选择 16k 模型，所有入口和执行层一致拒绝，原模型/历史/草稿不变；新会话或明确压缩后在容量足够时可选；覆盖大于、等于、小于边界及占用待更新 |
| 对话浮层 | 搜索按 Provider/ID/名称匹配，键盘只选择可用项，关闭不丢草稿；推理仅显示可用档位并标出当前/默认值，上下文详情与底部比例一致 |
| 上下文展示 | 数值与当前模型窗口匹配，压缩后可靠值未更新时不显示旧精确数，估算与未知可区分 |
| Token 统计 | 使用已知 usage 样例验证输入/输出/缓存与 reasoning 不重复；压缩后累计保留，按原 Provider 归属 |
| 持久记录与幂等 | 重放流事件、重启、恢复或克隆不会多计；重试/失败/取消分别记录已知消耗和未知部分 |
| 符号补全与普通输入 | `@`、`$`、`/` 的候选与键盘行为正确；中文组合输入、邮箱、Windows 路径、代码和 `$HOME` 不误触发提交或执行 |
| 多仓库引用与技能 | 重名条目明确来源，实际读取本任务文件；失效引用不替换为其他任务资源；组合输入不重复展开 |
| 命令与运行状态 | 应用命令调用真实操作而非发给模型；新会话保留任务，忙碌命令和扩展不能绕过写操作协调 |
| 定时任务配置 | 一次性、每日、每周和五段 Cron 按保存的 IANA 时区计算下一次触发；项目、Provider、模型、权限和提示词完整回显，修改只影响后续执行 |
| 定时执行隔离 | 每次触发在同一定时任务中创建新会话并发送一次提示词；会话不继承上下文或草稿但共享任务工作区，上次未结束时跳过并记录原因 |
| 定时历史会话 | 执行记录定位到对应会话；历史消息、工具结果和错误可查看，用户可继续对话且不会改变后续触发的新会话 |
| 定时失效与恢复 | Host 离线不补跑，重启、休眠、时钟回拨和夏令时不重复触发；项目／模型／凭据失效时明确失败且不静默替换，立即运行不改变后续计划 |
| Tailscale 私有入口 | Host 只监听回环地址，Serve 在指定 tailnet 身份下提供 HTTPS；未授权用户不可达，PiDock 设备权限仍独立生效 |
| 自建 Gateway 路由 | 桌面仅发起出站 WSS，手机经 HTTPS 访问指定主机；断线、重连、重复投递和多主机路由不串线，不存在任意 TCP 或原始 Pi RPC 透传 |
| 二维码配对 | 扫码自动打开正确入口；凭据短时、单次且不含长期令牌／项目名／本机路径，使用、过期或刷新后拒绝复用，最终设备仍需本机确认 |
| 远程设备授权 | 每台设备独立签发、轮换和撤销；撤销后现有连接与后续请求均失效，默认权限不包含文件、终端及高风险配置 |
| 公网入口防护 | Funnel 与自建 Gateway 均执行登录、授权、限流、审计和错误脱敏；网络可达不等于通过认证 |
| 浏览器控制 | Agent 操作用户可见页面、等待异步结果并读取失败证据 |
| 浏览器隔离与恢复 | 同站点不同账号互不覆盖；重新打开任务保留自身状态；恢复后请求目标正确 |
| 后台与退出 | 关闭窗口继续工作；明确退出停止所属资源，不误停其他任务或外部进程 |
| 安装包构建与发布 | 版本标签通过 GitHub Actions 生成同版本的 macOS arm64 DMG 与 Windows x64 EXE；文件名、内部版本和实际二进制架构一致，任一缺失或失败则不发布完整 Release |
| 安装与升级 | 两个平台从干净系统完成安装、首次启动、重开、覆盖升级和卸载；正式包签名有效，macOS 公证通过，升级和卸载不误删用户数据 |
| 真实同步查询 | 页面请求经过本地 BFF 和选定本地 Go 服务，有响应和运行实例归属证据 |
| 旧构建或陈旧协议 | 验证结果不会把未加载最新代码的运行实例标记为本次修改通过 |

工作区和进程行为可用临时 Git 仓库、可控小进程重复测试；它们用于测试隔离机制，不替代用户指定的真实业务验收。真实数据查询采用用户选定的非生产环境和既有登录流程。协议变更及外部回调安排独立用例，不为证明同步查询而修改共享业务数据。

macOS 和 Windows 分别记录实际通过的平台与架构。当前没有 Windows 运行结果；Windows x64 工具链仍须实际验证。已知的 Windows ARM64 生成工具缺口属于非目标架构限制，不阻塞本次 x64 发布，但不得据此声称支持 Windows ARM64。

## Out of Scope

- 首个同步闭环不承担异步解析、对账任务和 DTM 回调的完整验收；这些能力在后续里程碑独立设计。
- 自动创建任务专属数据库、缓存与消息资源。
- Telepresence 的自动连接、拦截及多人/多任务路由方案；保留远程连接扩展接口。
- Agent 断点调试与完整 IDE 调试器；保留使用外部编辑器的入口。
- 多个 Agent 在同一个任务中同时写代码。
- 不经明确操作自动提交、推送、合并或部署业务代码。
- 任意 shell 命令的操作系统级沙箱保证。
- Provider 账户账单对账、余额/配额查询，以及本应用之外的 Token 消耗统计；模型费用展示如后续增加需单独说明估价来源。
