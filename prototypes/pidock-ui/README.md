# PiDock UI 探索草稿

最终收口入口：会话状态卡可演示执行、审批、失败、停止和确认过期；「需要处理」定位跨项目会话；环境页查看生效配置；归档任务可预览清理清单。当前 A 为实现基线，B/C 保留作对照。规则见 [产品设计收口](../../docs/product-design-closure.md)，旧段落审阅状态按历史理解。全部操作仍为页面内存模拟，未发送、未清理或导出真实文件。

定时任务支持可选常用模板：每周仓库改动摘要（周日 18:00）、站会主题准备（周一至周五 09:15）、每周代码贡献统计（周日 19:00）、每日代码风险巡检（周一至周五 17:00）、每周发布准备检查（周五 15:00）。模板仅在新建定时任务时作为起点，选择后点击「使用模板」预填周期与提示词，名称仅为空或仍为上次模板名称时填入。保留项目、模型、权限、时区和工作区设置；结果处理写在可编辑提示词中，不新增发送配置。模板不会自行启用或运行；须完成任务创建。当前仅为内存交互原型。

问题：多仓库任务中，对话、服务运行与浏览器验证应该怎样分配空间，才能帮助用户发现缺失功能？

这是可丢弃的 UI 原型，不是桌面应用实现。模拟数据、主动选择的文件及粘贴的图片仅在页面内存中保存，刷新重置；不会读写业务仓库、启动业务服务、连接 Provider、注册系统调度或执行终端命令。业务页面只是示意，不代表真实站点已验证。

## 打开

在本目录运行 `python3 -m http.server 4319 --bind 127.0.0.1`，打开 <http://127.0.0.1:4319/?variant=A>。端口被占用时换用空闲端口，不停止其他进程。也可直接打开 [index.html](index.html)，无需安装依赖。

## 三种布局

- A — 对话优先：项目/任务侧栏，中央 Agent 对话，右侧运行、浏览器、文件与终端面板。
- B — 运行优先：服务卡片和本地依赖先行，对话位于辅助侧栏。
- C — 验证优先：准备代码 → 运行环境 → 浏览器验证 → 审阅交付，放大当前工作区域，对话持续可用。

工具区默认关闭，点击任务顶部图标或相关操作才打开对应标签，可逐个关闭或收起。底部浮动栏切换布局，URL 使用 `?variant=A|B|C`。非编辑状态下左右方向键也可切换。底栏显示当前任务、运行服务数量和浏览器控制者；切换布局保持模拟状态。

## 建议体验顺序

1. 查看默认任务，切换另一个共享仓库的任务；比较各任务的仓库和端口。
2. 新建任务、选择仓库及各自基准分支，再体验进行中添加仓库。
3. 编辑任务覆盖，切换到共享模板查看差异确认，以及本机私有配置。
4. 启停服务、切换本地/远程，进入浏览器并体验接管/交还。
5. 输入框支持直接粘贴剪贴板图片／截图，左侧「+」可选择文件；图片显示可移除、可放大查看的缩略图，其他文件保留附件名称。图片仅作本页预览，不上传；模型选择在右侧。输入 `@`、`$`、`/`，选择文件/技能或命令，切换 Provider，查看上下文和 Token 用量。
6. 归档并恢复任务，查看清理与交付所需信息。
7. 打开「定时任务」，创建周期规则并立即运行，从执行记录进入模拟会话；再查看「能力管理」和「远程访问」。

## 已覆盖与尚未展开

能力管理继续审阅；定时任务与五个含默认提示词的内置模板、远程访问方向已于 2026-09-21 确认。能力页区分 Pi 原生 Skills、Extensions、Packages 与 PiDock 通过 bridge Extension 接入的 MCP Servers；Package 负责安装版本，其他视图呈现运行资源和连接。新建任务时可选普通或定时，进行中列表标记类型；定时任务页支持一次性、每日、每周和五段 Cron，固定 Provider／模型、时区、会话权限及提示词。示例覆盖每周仓库改动摘要、每日站会主题和每周代码贡献度，结果如何保存或发送直接写在提示词中。每次模拟触发在同一任务内新建独立会话，历史会话可打开并继续对话；首版设计采用主机离线不补跑、上次仍运行时跳过及默认权限按需确认，真实运行时仍需验收。远程页提供推荐的 Tailscale 私有访问、自建 PiDock Gateway 和实验性 Funnel，共享设备授权和 PiDock 权限；自建模式由桌面主动连接 Gateway，不直接暴露 Pi RPC 或本机端口。点击「扫码添加」会在浏览器本地生成包含短时单次凭据的二维码，手机扫码自动打开配对链接；刷新后旧码失效，成功配对仍需本机确认。文件／终端默认不向手机开放，远程操作仍受现有会话权限和执行协调约束。全部调度、连接和设备均为内存示例，没有注册系统计划、启动 Tailscale／Gateway、联网、真实配对或远程执行。技术边界与一手来源见 [调研记录](../../docs/pi-extensibility-and-remote-access.md)，交互状态见 [UI 审阅记录](../../docs/ui-prototype-review.md)。补充逻辑位于 schedules.js 与 capabilities.js；已回填规格、领域术语和验收计划，新增工单仍待整体拆分审阅。

混合目录与软链接方案于 2026-09-21 已确认：一个项目可同时关联多个 Git 仓库与多个普通目录，不再二选一。项目编辑中保留仓库选择，普通目录逐行新增名称和完整路径；任务按需混选或只选一种，也可追加。Git 仓库沿用最新远程基线及独立 worktree，普通目录在任务文件夹内创建软链接，不复制文件、不初始化 Git；即使仅选普通目录也创建 ASCII 任务文件夹。pi 以任务文件夹为统一工作目录，不依赖额外目录参数；环境可暂不使用。文件与终端面板可选择具体目录并展示其工作路径，@ 引用区分两类来源。项目中新增目录不自动加入已有任务。链接使用稳定英文数字名称，创建预览和文件／终端同时展示链接路径、原始目标及共享修改提示；追加沿用任务位置，清理仅移除受管理链接、不删除目标。共享普通目录的真实路径授权与跨任务写协调、pi 工具遍历链接的兼容性、Windows 链接类型／权限、原生目录选择／实际类型检测与迁移仍待后续验证，所有路径与文件均为内存示例。已回填规格、领域术语及相关工单草案；真实运行时仍未验收，工单未发布。补充逻辑位于 directories.js。

输入框左下角「+」后增加当前会话权限入口，就地浮层可选「只读／默认权限／自动执行」，选项含范围与询问说明。2026-09-21 用户已确认：只读不执行有副作用的操作；默认允许任务内文件读写、命令与浏览器操作前询问；自动执行允许任务内操作无需逐次询问，各档位仍遵循共享模板确认规则。权限按 Session 独立保留，新会话默认「默认权限」，示例代码审查会话初始「只读」，切换保留文字／附件草稿。现有只读模拟门禁改为读取权限选择；真实工具审批、系统隔离与派生执行尚未实现。此组入口、档位及后续请求生效原则已同步规格和 09/10/14/15 号草案，真实审批与执行边界另验；其他管理、Subagent 和图片具体交互仍待各自确认。补充逻辑位于 permissions.js。

图片粘贴交互继续审阅：聚焦输入框后用 Cmd+V／Ctrl+V 加入剪贴板图片，可连续追加、移除、预览，支持纯图片及图文模拟发送。图片草稿按任务／会话保留，发送后在消息内继续显示；普通文字粘贴保持原行为。未启用图片输入的模型保留附件并提示切换、阻止发送。默认 Claude Sonnet 示例配置启用图片输入，仅用于演示，不代表检测了实际模型能力。补充逻辑位于 attachments.js；只响应主动粘贴／文件选择，不主动读取系统剪贴板或获取截图。刷新清空，尚未连接上传、模型推理、持久存储或图片格式转换。

当前任务的会话标签下增加 Subagent 列表，点击卡片在右侧查看任务说明、消息、可展开工具输出与结果；顶部也有查看入口。侧栏只读，主会话草稿保留，关闭后恢复原布局及工具面板。列表及所选记录按任务／会话分别保留，新会话为空。两项默认示例为运行中和已完成，均不启动真实子代理或实时生成内容；界面仍待本组确认。补充逻辑位于 subagents.js。

跨项目并行已由用户明确：不同项目中的任务／Agent 会话可同时执行，项目切换只改变视图。同任务仍按既有规则协调写操作；原型仅保留各项目内存状态和模拟运行标记，没有接入真实并发 Agent／服务，实际执行仍需验收。

本轮继续审阅会话、项目与环境管理：会话栏的归档图标打开管理列表，可归档／恢复会话；左上角项目选择器可新建、编辑、切换和删除项目；「环境与服务」提供环境新增、编辑及删除。有任务关联的项目／环境目前展示删除阻止原因，无引用项可完成内存删除。删除约束及最后一个会话归档后自动新建会话的行为仍为待审阅方案。

环境变量在 KEY／VALUE 两列表格中直接新增、修改和删除，KEY 保存前检查为空、格式及重复，VALUE 可以为空。草稿按项目／环境／配置范围／任务分开；共享模板保存前预览字段差异并模拟新版本。真实配置快照、服务配方保存与运行解析尚未接入。主交互位于 app.js，管理界面与列表编辑的补充逻辑位于 management.js，两者由入口页按顺序加载。

本机设置展示用户指定的默认应用配置目录 `~/.pi/dock`，配置文件暂拟 `config.json`；任务根目录仍单独配置。此原型不向该目录写文件，不保存真实凭据。上述新增界面待本组审阅收敛后集中回填正式规格，详情见 UI 审阅记录末节。

新建任务支持中文显示名称，任务目录采用独立自动生成的英文数字标识；表单预览任务文件夹，文件视图展示仓库子目录，追加仓库沿用原任务目录。目录不取自显示名称或可编辑分支。此部分已于 2026-09-20 获用户确认：自动目录采用 `task-<8 位英文数字标识>`，默认分支为 `task/<同一短标识>` 且可独立编辑。原型路径是示意，不创建真实文件夹；正式实现需处理目录冲突与跨平台路径。

「本机设置」可保存默认任务根目录到页面内存，新建时可单次覆盖并实时预览路径，已有任务保留原路径。仓库基线改为明确的远程分支，创建／追加前模拟获取最新提交；可展开「原型演示场景」查看获取失败、保留表单和重试流程。文件面板回显所选远程分支与模拟提交。此组交互已确认并集中回填正式规格、02/03/15 号草案及验收计划。未执行真实 fetch、目录检查或 worktree 创建，原型内存行为不代表持久化与 Git 验收通过。

添加和编辑 Provider 界面已于 2026-09-20 完成本轮审阅。模型列表的「同步模型列表」提供本地示例候选；模型 ID 支持直接填写、下拉选择、输入筛选及方向键/Enter 选择。显示名称默认跟随 ID，手动修改后保留，清空后恢复跟随；保存后可重新编辑。同步保留现有配置，修改地址或协议后需重新同步。当前不调用真实模型发现接口，也不据候选 ID 推断能力。

主操作能改变内存状态，包括新任务、服务启停、会话草稿、模型切换、变量编辑、浏览器接管和归档恢复。配方编辑、导入、仓库绑定、交付与清理属于表单/决策界面示意，尚未实现真实执行。Token 图表为固定样例，不作为统计实现。

对话中的模型、推理和上下文详情已改为入口旁的小浮层，并于本轮获得确认。模型支持按 Provider 分组及搜索、键盘选择；推理标明当前与默认档位；上下文显示占用、窗口及百分比，详情提供模拟压缩。当前模型跟随目录而目录未接入时，不虚构可选推理档位；可通过模型设置配置子集体验。

上下文超过目标模型窗口时禁止切换，候选置灰并显示原因，对话浮层与 Provider 页选择器一致，切换动作也有校验。默认示例会话为 24.8k，「团队轻量模型」为 16k，因此不可选；新会话或先进行模拟压缩后容量足够时可选。示例模型的窗口和用量只用于交互演示，真实运行时、待更新状态与边界仍需正式接入验证。
