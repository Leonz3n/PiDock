# PiDock UI 设计评审原型

2026-11-02 最新入口：**[首版 UI 重设计](http://127.0.0.1:4319/mvp-review.html?variant=A)**。以 #135 缩减后的首版为范围，提供 Apple 侧栏与扁平分栏两版；说明见 [MVP-REVIEW.md](MVP-REVIEW.md)。以下为旧的全功能原型记录，不作为当前首版范围或新视觉基线。

状态：待用户选择方向。此目录内的 `redesign*` 文件仅用于设计评审，尚未接入生产应用。

2026-10-23：用户倾向 Apple 风格，并要求补齐功能。新的 [Apple 功能评审版](http://127.0.0.1:4319/apple.html) 复用完整内存原型的工作流，增加 Apple 样式和浏览器标记等交互，详见 [APPLE-REVIEW.md](APPLE-REVIEW.md)。下述三版保留为视觉对照，不代表完整产品范围；A 旧视觉稿中的绿色状态不沿用到新的 Apple 版。

本轮问题：PiDock 应采用哪种视觉方向，以及对话与运行／验证结果应该怎样分配空间？

从仓库根目录运行：

```sh
python3 -m http.server 4319 --bind 127.0.0.1 --directory prototypes/pidock-ui
```

浏览器打开 <http://127.0.0.1:4319/redesign.html?variant=A>。

| 方案 | 视觉与信息层级 | 链接 |
| --- | --- | --- |
| A · Apple 原生 | 浅色工作台、任务侧栏、对话为主、运行结果放 Inspector | [?variant=A](http://127.0.0.1:4319/redesign.html?variant=A) |
| B · 二次元机能 | 暗色战术终端、任务序列、工具执行与状态反馈 | [?variant=B](http://127.0.0.1:4319/redesign.html?variant=B) |
| C · 融合分屏 | 收起导航为图标栏，对话与大面积验证画布并排 | [?variant=C](http://127.0.0.1:4319/redesign.html?variant=C) |

底部按钮或左右方向键切换方案；输入框内的方向键用于编辑文本。C 版标签栏内的方向键切换验证内容。

可以体验：

- 发送消息：Enter 发送，Shift+Enter 换行；中文输入法选词时不发送。
- 新建演示任务、查看空状态、返回示例任务。
- A/C 的执行摘要展开与折叠。
- 运行／验证面板展开与关闭，小窗口下通过遮罩或 Escape 关闭。
- 模拟停止和启动服务，观察服务数量及状态变化。
- C 版浏览器、代码变更、服务标签，以及从对话结果跳转到对应标签。

窗口策略：A/B 在宽度不超过 1180px 时将 Inspector 改为覆盖抽屉；宽度不超过 760px 时收起任务侧栏。C 保留分屏至 760px，再将验证画布改为抽屉。评审工具栏占用独立底部区域，避免覆盖消息输入框。

所有任务、仓库、服务、代码、金额、浏览器结果与回复均为模拟数据。输入仅存在于当前页面内存，不调用模型、不启动真实服务、不保存任务；刷新恢复初始状态。浏览器视图是 HTML 示例快照。字体使用本地系统回退，无外部字体依赖。

评审时优先确定：整体视觉方向、是否保留常驻任务侧栏、验证工作台是否与对话并排。可以组合不同方案的局部设计。方向确认后另行编写生产实现规格，重写正式组件。
