# 前端与桌面技术栈设计

2026-09-21。继续设计，未启动实现。产品规则以[首版规格](../.scratch/pidock-mvp/spec.md)为准；本文补充组件职责和草稿向正式界面的迁移方式。工单 01 已实测否决 Electrobun，桌面壳改为 Electron + Bun Host；证据与限制见[可见页面控制与桌面壳验证](browser-automation-validation.md)与[运行时调研](desktop-runtime-research.md)。

## 运行时边界

- Bun 是 PiDock Host 的运行时，也是包管理与项目脚本的默认入口。用户业务仓库继续使用其自身的工具链，不强制迁到 Bun。
- Electron 必须锁定版本，主进程运行其内置 Node，原生集成与窗口管理由 Electron 负责；Bun 只承担 Host 运行时，不替换 Electron 主进程。安装包必须验证实际运行时与嵌套 Bun Host 可执行文件。
- React 在 Electron 的 Chromium 渲染环境运行。使用 Bun 不意味着 React、Electron 渲染进程或 Bun Host 也运行在 Bun 中。
- 任务浏览器持久分区归任务，页面句柄归具体视图并绑定任务；同任务标签页与登录弹窗复用分区，不同任务隔离。
- 自有界面通过受控接口访问 Host；任务网页使用独立的浏览器视图，不能获得自有界面的本机能力桥接。渲染器布局、窗口和平台集成属于桌面适配层，业务组件不直接导入桌面壳 API。
- Host 是任务、会话、审批、调度与受管执行的权威来源。前端缓存不执行调度、不决定权限，也不重复维护一套写锁。02 接入真实 pi 工具前建立基础权限门禁，04／06 的服务与浏览器工具复用；09 的权限集成验收是 07 真实业务验证的前置条件。
- 首版采用客户端 React 应用。构建工具建议从 Vite 评估，Bun 负责启动工具；最终版本、插件和打包加载方式在 20/02 固定，不把使用 Bun 误解为必须只使用 Bun 自带 bundler。

## TanStack 的采用范围

“全家桶”按同一生态优先选型：适用能力优先使用，避免为了装全包引入重复职责。以下是设计分工，不代表已安装或验证。

| 能力 | 组件 | PiDock 中的用途与边界 |
| --- | --- | --- |
| 导航 | Router | 项目、任务、会话、设置及统计视图；保存可恢复的导航状态，不在 URL 放凭据或正文 |
| Host 数据 | Query | 项目列表、会话快照、Provider、用量等读取与缓存；桌面受控接口和移动端请求可提供不同适配器 |
| 表格 | Table | Token 明细、执行记录等排序、筛选与列模型；标记和样式由 React/Tailwind 实现 |
| 长列表 | Virtual | 长会话列表、日志及消息历史；测量动态高度，验证流式更新、图片加载、滚动锚点与历史定位 |
| 表单 | Form | 项目、环境、Provider 和定时配置；前端即时校验改善反馈，Host 保存时仍独立校验 |
| 客户端状态 | React 局部状态，必要时 Store | 浮层、工具区、选择和编辑中状态；跨组件共享确有需要时引入 Store，不复制 Query 中的 Host 状态 |
| 全栈及同步 | Start、DB 暂不默认引入 | 当前无 SSR 或独立客户端数据库同步需求；未来引入需说明解决的问题与现有 Host 状态如何衔接 |

Router 的加载器复用 Query 的读取与缓存，不再各存一份业务快照。Query key 包含必要的 Host、项目、任务及会话身份；切换目标、断开连接或撤销远程设备时不能误显示另一目标的数据。

流式回复通过事件订阅接入，按会话身份与顺序增量处理；断线后按 Host 的恢复机制重新获取快照或续接事件。Query 不是事件日志，不用每个 token 触发全量查询。发送、批准、运行和清理等有副作用的操作不因组件重挂载或连接恢复自动重试；界面只在 Host 确认后展示执行成功。

输入草稿、滚动锚点与表单未保存值和查询缓存分开管理。需要跨重启保留的草稿按已有规格交给持久化入口，不能依赖 Query 缓存生命周期。

## 复刻 UI 草稿

现有 `prototypes/pidock-ui/` 的 vanilla JS 可以继续作为已确认的视觉与行为参照。简单布局、配色和文案探索仍允许 vanilla JS；需要验证真实组件、路由、表单或虚拟滚动时使用 React/Tailwind/TanStack。无需仅为技术栈一致改写现有草稿。

工单 20 是可演进的正式渲染层基线，按 A 对话优先布局复原草稿。它与快速草稿用途不同：可复用展示组件、样式和界面交互，但模拟数据与模拟执行必须集中放在可替换的适配层，不能散布到组件中成为生产业务逻辑。20 不预设最终 Host 传输协议，02 定义接口后替换模拟适配器。

先统一颜色、字体、间距、圆角、层级、面板宽度及状态样式，再复原工作台框架和组件。Tailwind 使用统一设计变量，保持蓝灰基线、不使用绿色、π 居中。TanStack 的无样式能力有利于保留原稿外观；不因为选组件库而套用其默认视觉。

对照覆盖常用桌面尺寸和窄栏、字体差异、中文输入法、键盘和焦点、浮层遮挡、工具区开关、滚动与草稿保留。使用同一组模拟数据逐页截图和走查，差异记入 20。四个会话标签等小集合不强制虚拟化；长列表按实际规模验收。20 的浏览器验收不能代替 21 的 Electron 桌面验证、02 的桌面集成验收及 15 的双平台安装验收。

移动端沿用 React/Tailwind/TanStack、领域数据类型和适用组件，通过远程授权接口接入同一 Host；桌面桥接和本机文件 API 不进入移动端组件。移动布局按手机工作流设计，不直接缩小桌面工具区。
