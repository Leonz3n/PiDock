# 设计方向对照与未决事项

更新：2026-11-02。本文件只做对照和记录，不替代 #135 / #1 的产品范围，也不表示任一方向已被验收。

## 1. 共同前提

两套候选都从当前首版规则出发，而不是从旧工作台 A 复刻：

- **层级**：项目 → 任务 → 会话；不增加「工作空间」。
- **工作区**：已有目录与独立 worktree 都必须在首版可用；混合来源任务逐项显示事实，不能用一个「独立 worktree」标签概括全部。
- **任务事实**：模式、路径、分支、提交常驻可见，使用等宽字体；不放在 hover、tooltip 或二级弹层里。
- **首版能力**：定时任务；Provider / MCP / Skills；会话生命周期；任务归档与清理；归档任务可恢复。
- **视觉硬约束**：全界面无绿色；完成/成功用 slate，运行中用蓝，关注用琥珀，危险用红；无渐变、毛玻璃、emoji 图标、常驻右侧大详情栏。
- **桌面尺寸**：1440×900 为设计画布，720×560 为最小验证窗口。
- **范围外**：服务编排、环境模板、内置浏览器、内置终端、远程访问、复杂用量报表、文件/差异工作台。

## 2. 结构性对照

| 维度 | Quiet Ledger | Stitch Apple | 需要拍板 |
| --- | --- | --- | --- |
| 气质 | 安静台账：暖纸、墨蓝、发丝线，偏“审计与记录” | 冷灰白桌面工具：亮蓝、扁平控件，偏“Apple 工具” | 品牌方向 |

## 3. 两套各自的强项与风险

### Quiet Ledger

**强项**

- 暖纸 + 墨蓝的层级更分明，长时间阅读会话和审批记录不刺眼。
- 任务事实条、归档/清理的“已结算”文案更接近产品语义，不容易把完成误读成“成功绿灯”。
- 有完整 Figma SVG 和可复现的参考图生成脚本，改版成本低。

**风险**

- 暖色底在部分 Windows 显示器上可能偏黄；需要用实际屏幕复核。
- 11 张参考图没有单独覆盖 Skills 和 720×560，需要补图或明确复用规则。
- 视觉上更“设计感”，若实现时偷懒会退回成普通卡片式后台。

### Stitch Apple

**强项**

- 更接近桌面工具的密度和控件习惯，窄窗口、任务信息、失败现场有独立画板。
- 14 张参考图覆盖的页面/状态更多，CHECKLIST 和 SOURCES 的评审痕迹更完整。
- 扁平控件实现成本低，容易在 Electron 里做到像素级接近。

**风险**

- 冷灰白 + 亮蓝更容易滑向通用 SaaS/系统设置，项目→任务→会话的“台账感”较弱。
- 没有 Figma 矢量稿，重建组件时容易出现“图上看像、实现不像”。
- A/B 两版侧栏仍留在原型里，若评审时混看，会误以为两套都是目标。

## 4. 建议的评审顺序（不代替选择）

1. 先看两套的**任务页**：同一任务、同一混合来源、同一失败/审批状态，比较事实条、对话宽度和详情入口。
2. 再看**收尾**：归档、清理、恢复三态，确认完成色不是绿色、危险操作有足够区分。
3. 再看**720×560**：侧栏、任务事实、会话标签、输入框是否仍可用。
4. 最后看**项目页与能力页**：项目树是否过深，Provider/MCP/Skills 是否被做成三套不同导航。
5. 选定后只保留一套作为实现基线；另一套在 README 标记归档，不删除，便于回看。
