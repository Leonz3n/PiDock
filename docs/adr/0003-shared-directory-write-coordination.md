# 共享普通目标的写协调：真实路径键、链接不等于文件隔离，具体跨任务协调归 #11

Status: accepted (2026-10-12; #6 盒 13, #11)

#6 盒 13 要求「跨任务/项目共享普通目标的写协调方案须在实现该共享访问前细化；与 09 对接真实路径授权和写协调，**不能**用任务 ID 锁或不同链接名称声称文件隔离」。本决策记录该方案的归属与已经成立的部分，并明确未完成的部分归谁。

**归属已经由代码写明**：`packages/shell/src/host/path-coordination.ts` 的文件头自称「Real-path write coordination across tasks for **[PiDock 09] (#11)**」。也就是说**具体的跨任务真实路径写协调是 #11 的交付物**，#6 的义务是**先细化方案并禁止假隔离声明**，不是另起一套协调器。

## 已经细化的方案（规则层可核）

任务级写操作权（`write-coordination.ts`）只回答「同一任务内谁在写」。任务之间的真实共享目录是**另一层**协调，按**解析后的真实路径**判定，而不是词法路径，也不是任务 id：

- **键 = 真实路径**（`realpathSync`，不是词法路径；`classifyRealPath`，`path-coordination.ts:104`）。**不得用任务 ID 锁**，也不得靠「不同链接名称」声称文件隔离。
- **重叠即串行**：两个任务写同一真实路径或互为祖先／后代 → 后者被拒并**说明持有者**（`shared-path-locked`，`SharedPathCoordinator`，`:158`）。段感知：`/a/bc` 与 `/a/b` **不**视为重叠（`:52`、`:65`）。嵌套链接按**祖先真实路径**判定重叠。
- **不重叠即并行**：不引入项目级／全局单会话锁。
- **链接改指即换键**：真实路径变化后旧键随释放消失，新键重新判定，不沿用旧归属。
- **表有界**：live path key 数量有上限（`:20`），不是无界增长。规则是纯函数／纯状态机，Host 派发、渲染层展示与测试共用同一份判定，避免各写一份而漂移。

接线：Host 侧 `sharedRoots()`（`task-host.ts:1277`，来源是任务记录的 `dirLinks`）→ `pathScopeOf`（`:1296`，走 `classifyRealPath`）→ `claimPathScope`（`:1326`，在真实副作用工具前声明）；Host 装配见 `host.ts`。

**链接永远不是文件隔离**：普通目录来源是**链接到原目录的共享视图**，写穿链接就是改原目录。因此界面必须按名说明「共享原目录，文件未隔离」（已上线并有测试钉住）。任何以「文件已隔离」措辞描述链接的界面文案都属缺陷。

## 尚未完成的部分（明确归 #11，不在 #6 记功）

协调器实例是**每 utilityProcess 一个**（`PerTaskHostRegistry` 为每个任务 fork 一个 Host），所以**一个进程内的表无法真正调解两个进程里的两个任务**——这是 recon 指出的唯一实质缺口。本决策不把它算作 #6 的交付，也不声称跨任务写协调已经在生产生效。

**可用的原语已经存在**：#6 盒 9 为「并发创建共享仓库 worktree」建了**应用私有**（`<userData>` 下）、**按各来源仓库真实路径键控**、**单次原子 `fs.open(...,"wx")` 获取**、**pid + 启动时间识别持有者**、**具名失效策略且绝不静默强夺**的跨进程锁（`packages/shell/src/main/worktree-metadata-lock.ts`）。若 #11 需要把共享目标写协调扩到跨进程，应当复用这一原语与「真实路径键」的同一条规则，而不是新造第三种锁。

## Considered Options

- **#6 自己实现跨进程共享目标写协调**：能补上「每进程一个」的缺口，但 `path-coordination.ts` 已自称属 #11，#6 正文也只要求「与 09 对接」；由 #6 实现会与 #11 的交付物重复，并让同一规则出现两套所有者。不采用。
- **只记录方案、不写代码**（采用）：#6 盒 13 的正文是「方案须**在实现该共享访问前细化**」，属规则层义务；已经成立的部分（真实路径键、段感知重叠、拒绝并说明持有者、链接不等于隔离）在代码里可核，未完成的部分明确归 #11。代价是盒 13 只能记为部分交付。
- **把协调器改成全局单会话锁**：与既有规则直接冲突（「不引入项目级／全局单会话锁」），且会把互不重叠的写入错误串行化。不采用。

## Consequences

- #6 盒 13 记**部分交付**：方案已细化并在代码中成立；**具体跨任务共享目标的跨进程写协调仍归 #11**，不由 #6 记功。
- 任何界面都不得以「文件已隔离」描述普通目录链接；链接行必须同时给出共享原目录说明。
- 后续若在 #11 扩展跨进程协调，键仍须是解析后的真实路径，复用 #6 盒 9 的应用私有原子锁原语，并保持「拒绝时说明持有者、无效键可重新判定、表有界」三条既有性质。
- 本决策只确定归属与已成立规则，不表示跨任务写协调已在生产跨进程生效。
