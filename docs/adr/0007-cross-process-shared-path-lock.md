# 跨任务共享真实路径写协调的跨进程锁：一条键规则、一种记录、一种具名恢复

Status: accepted (2026-11-08; Pencil T06 / #141)

ADR 0003 把「具体的跨任务真实路径写协调」归给 #11，并写清了已经成立的部分：键 = 解析后的真实路径、祖先／后代即重叠、拒绝说明持有者、链接不等于隔离、表有界。它同时指出了唯一实质缺口——`path-coordination.ts` 的协调器**每个 Host 进程一个**，所以两个真实 Host 进程（一个任务一个 `utilityProcess`）写同一目录时根本不在同一张表里。本决策记录 #141 如何把这个缺口补上，并固定锁的记录格式与恢复规则，使「受管保护」这句话有可核的实现。

## 决策

1. **跨进程锁复用 #6 盒 9 的原子原语，不新造第三种锁。** 位置仍是应用私有目录（`<userData>`），目录名 `shared-path-locks`；获取仍是单次独占创建（`fs.open(...,"wx")` 后写入并 `fsync`，或把**完整记录**用 `fs.link` 从临时文件发布）。绝不使用 stat-then-write。键的文件名是真实路径的 SHA-256，所以应用数据目录里不出现用户路径。
2. **一条键规则，两层实现。** 进程内表（`SharedPathCoordinator`）与跨进程锁（`host/shared-path-lock.ts`）共用同一个规则模块：`normalizeScopePath`、`pathScopeOverlaps`、`scopeKeysFor`。键**永远是** `fs.realpath` 解析后的路径；不用任务 ID、不用词法路径、不用链接名。**每次获取都重新解析**，所以链接改指只会产生新键、旧键随释放消失——改指永远不会扩大既有授权。
3. **一种记录格式**（`version: 1`）：

   | 字段 | 含义 |
   | --- | --- |
   | `key` | 规范化后的真实路径（冲突键本身） |
   | `taskId` / `sessionId` / `label` | 持有者身份，用于拒绝文案（不是只给 pid） |
   | `hostInstance` | 该 Host 实例的 nonce；实例在锁目录留有 `host-instance-<nonce>.json` 标记 |
   | `pid` | 持有进程 |
   | `at` | 获取时间（ISO），用于年龄与竞争决胜 |

4. **重叠 = 同一路径或互为祖先／后代（段感知）**。因为祖先与后代是两个不同的文件，「一个键一个文件」不足以判定一次获取，所以获取分两步：先独占发布自己的完整记录，再读取目录内**所有**记录判定重叠。两个同时开始的竞争者会互相看到，因此胜者由 `(at, hostInstance, pid, key)` 的**全序**决定：较晚的一条让出，并在返回拒绝前撤回自己刚发布的记录。任何时刻最终只剩一个持有者，被拒的一次调用不留下任何东西。不重叠的目录**并行**，不引入全局单会话锁。
5. **失效持有者按名恢复（`lock-owner-dead`），绝不静默强夺。** 「可证明已死亡」= `process.kill(pid, 0)` 答 ESRCH（进程确实不在），**或**命名 Host 实例的标记文件已不存在（pid 被回收的情况）。恢复时把旧记录原子 `rename` 成持久凭据 `<hash>.stale-<uuid>.lock`，并announce 被驱逐的任务／会话／标签／Host 实例／pid／开始时间。**仍然活着**的持有者、**记录不可读**、**锁目录不可用**一律具名拒绝（`shared-path-locked` / `shared-path-lock-unreadable` / `shared-path-lock-unavailable`），不做任何接管；目录记录数有上限（`MAX_SHARED_PATH_LOCK_FILES`），超出即拒绝而不是无界扫描。
6. **释放覆盖完成、取消与 Host 退出**：一次尝试结束、确认结算、`task/cancel`、Host 退出都会释放；部分释放沿用表的 `keepPaths` 语义（失败的一次只撤回自己新增的键，未结算的确认仍持有原键）。释放前重读记录、只删除**本进程写的那一条**，所以一个迟到的释放永远不会释放别人后来取得的锁。
7. **共享 Git 目录与普通目录走同一条规则。** `existing-git` 任务就地使用原检出，那是与普通目录链接同一种「共享真实路径」，因此 `sharedRoots()` 与 Agent 工具边界都把 `sharedRepos` 当作共享根，按真实路径获取同一把锁。
8. **界面只在真实接线完成后说「受管保护」**，并必须同时说出外部编辑器的写入按 ADR 0006 明确豁免；不得以「文件已隔离」或安全徽标冒充保护。

## Considered Options

- **给每个真实路径一个文件、只做同路径互斥**：实现最省，但祖先／后代重叠会被放过（`/a` 与 `/a/b` 是两个文件），等于把 ADR 0003 的重叠规则在跨进程层丢掉。不采用。
- **在 main 进程集中做协调（IPC 回合）**：能把两个 Host 串行化，但把一次文件写入的延迟绑在 main 的事件循环上，并给 main 增加一个必须与 Host 崩溃对齐的状态机；原子锁只需一次 `open`/`link`，且崩溃后的恢复是文件而不是内存状态。不采用。
- **只靠 pid 判活**：pid 回收会让死锁读成活锁（永久拒绝），或让活锁被误判成死的（静默强夺）。因此加入 Host 实例 nonce 标记作为第二证据。采用。
- **发现失效就静默删掉重建**：会让两个竞争者同时「接管」同一记录，等于两个持有者。因此接管只通过一次 `rename`（原子、唯一）完成，并保留凭据。不采用。

## Consequences

- 两个真实 Host 进程写同一或重叠真实路径时互斥，拒绝文案带实际持有者（任务／会话／Host 实例／pid／年龄）；不重叠目录仍并行。
- 崩溃（含 SIGKILL）不会永久阻塞：下一次获取按 `lock-owner-dead` 接管并留凭据；正常完成、取消与退出则直接释放，不留记录。
- 残留边界具名：pid + 实例标记不是操作系统级 fence；一个被外部删除标记的活实例可能被误判为死（记录与凭据仍留痕）；Windows 上目录 `fsync` 被跳过（`node:fs` 无该语义），原子性依赖 `link`/`rename` 本身。
- 本决策不改变 ADR 0006：外部编辑器的写入不参与协调，界面不得因此暗示「已隔离」。
