# 服务依赖声明归属共享模板，任务只做选择与覆盖

Status: accepted (2026-10-12; #7, #10)

服务依赖声明（**调用依赖**与**启动前置条件**）保存在**按环境的共享模板**中：共享模板是以项目配置文件保存、可通过版本管理复用的启动方式、环境变量及服务依赖声明（GLOSSARY 共享模板）。业务默认配置仍由业务仓库自身维护并随任务代码检出，服务按自身规则读取（GLOSSARY 业务默认配置）；共享模板是覆盖层，不是读取方。#10 的组计划**读取**这些声明得到真正的调用/前置边，任务的本地端口与**依赖地址**属于任务覆盖（GLOSSARY 任务覆盖），只作用于当前任务，不写回共享模板。

因此：#7 盒 1 的验收面**包含**按环境的依赖声明字段（其正文枚举只列了启动命令、参数、工作目录、端口与健康检查，以 GLOSSARY 共享模板的定义为准）；#10 盒 1「实际依赖去向」显示的是按声明与任务覆盖**解析后的去向**，盒 4 的「先监听再互验」由这些边驱动。**没有声明就是没有边**：面板继续按名显示「无依赖边（未做互验）」，不得为了点亮「已互验」而合成依赖边。声明指向不存在的服务、或在同一环境下出现冲突时，必须明确报错，不得静默丢弃该单元或默认成空图。

## Considered Options

- 依赖声明归 #10 盒 1（任务内独立的单元/依赖选择，不进模板）：任务内选择靠近「一次启动所需组合」，但违反 GLOSSARY 对共享模板的定义；依赖图无法随项目版本复用或跨任务共享，任务内的临时选择会被误当作权威，且同一服务在两个任务里会得到两套互不可见的依赖事实。
- 只放共享模板、不允许任务覆盖：依赖图权威单一，但本地端口与依赖地址本就属任务覆盖（GLOSSARY 任务覆盖），会被迫通过修改共享模板来改地址并互相影响，正是 GLOSSARY 明确要避免的「将任务覆盖称为环境模板修改」。
- 模板按环境声明 + 任务选择与覆盖（采用）：依赖图可复用且可按环境区分（不同环境可有不同的远程依赖选择与前置条件），任务的本地地址覆盖不污染共享模板。代价是模板 schema 需增加按环境的依赖声明字段，并做缺失引用与冲突校验，#7 盒 1 的验收面随之扩大。

## Consequences

- `ServiceTemplate` 按环境持有依赖声明；写入沿用既有封印：不得把凭据或本机私有值写进共享模板，损坏文档与缺失引用**明确报错**而非默认空图。
- #10 的计划从声明取边；没有声明即没有边，**不得合成边**，对应面板按名显示「无依赖边（未做互验）」。
- 验收顺序：#7 先建「按环境」维度与依赖声明，#10 再读取；#10 盒 2 的按环境绑定与本决策互为前置。
- 本决策只确定归属，不表示已实现：模板声明、任务覆盖与计划取边接线完成后分别验收。
