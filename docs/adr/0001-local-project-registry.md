# 本机注册表持有项目身份和任务归属

Status: accepted (2026-09-28; #35)

项目是可复用的仓库、普通目录、服务和环境集合，不是任务目录或单个仓库。本机受信任的 main 层持久化不可由名称或路径推导的稳定 Project ID、项目定义及任务到项目的关联；任务根目录索引只负责发现任务，不代表项目归属。界面通过受限接口读取这些数据，不得用 `memoryHost` 项目或合成 ID 填补缺失记录。

历史任务默认未归属，仅用户明确选定项目后才能认领；名称、仓库和目录相同都不是自动关联依据。重命名不改变项目身份；项目仍有关联任务时拒绝删除，须先由用户显式解绑或转移。任务目录缺失、被移动或记录身份不符时，关联不可指向另一任务，应显示待修复状态。注册表损坏时读取失败并提供修复途径，不静默回退演示数据。

## Considered Options

- 让每个 `task.json` 的 `projectId` 持有关联权威：任务文件可自描述，但旧任务及覆盖根需要逐个迁移，项目定义与多处任务文件的写入不能原子提交，移动或部分失败时还需跨文件恢复。
- 本机项目注册表统一持有定义与关联（采用）：一次受控写入可以保持本机项目与归属的一致性，不修改旧任务磁盘格式；代价是任务导出/移动时必须另行设计受控关联迁移，读取关联时仍需核验实际任务身份。

## Consequences

项目注册表应由 main 串行写入、原子保存并有版本/备份与损坏恢复规则；任务关联必须校验持久任务身份，不能只凭任务 ID 猜测目录。#36 的覆盖根索引独立实现。真正的项目创建、历史任务认领、桌面列表和任务创建接线分别验收，不因本决策自动视为已实现。
