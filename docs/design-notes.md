## 用户已明确的目标与边界

- 基于 pi AgentSession，支持 macOS 和 Windows。
- 一个任务关联多个 Git 仓库；任务进行中添加仓库也要准备任务独立的 worktree。
- 两个任务可包含相同仓库，各自修改不互相影响。
- 配置应支持图形化管理，按环境组织，且 Agent 能直接使用。
- 当前主要阻力是手写配置，以及必须推送、合并并部署代码之后才能让 Agent 继续验证。
- 目标闭环：修改代码 → 启动任务本地服务 → Agent 测试验证 → 根据结果继续修改。
- 本地可以只启动有需要的服务，例如 A、B、C；其他依赖 D、E、F 使用远程环境。
- 本地 A 应自动使用当前任务的本地 B、C。
- 并行任务支持代码与本地进程隔离。首版数据设施的复用边界见下方已确认策略。
- 首版调试覆盖启动/停止服务、日志、测试及浏览器验证，保留使用 VS Code 进行断点调试的入口；Agent 断点调试不在首版范围。
- 包含内置终端、浏览器和文件浏览。
- 内置浏览器必须支持 Agent 高效控制，以 Codex 的使用体验为参照。
- Telepresence 的具体使用方式继续待定。

## 已确认的配置与浏览器策略

- 可共享的服务与环境模板保存为项目配置文件，可通过 Git 在不同电脑或成员间复用，由图形界面管理。
- 业务仓库已包含默认配置文件，相关服务支持通过环境变量调整配置。运行时直接使用当前任务 worktree 中的默认配置文件。
- PiDock 的共享模板主要描述启动方式、环境变量、变量引用和服务依赖；不另行维护业务服务完整配置文件的副本。
- 环境选择、任务端口和本地依赖地址通过服务支持的环境变量注入启动进程；准备运行环境不需要复制或改写业务默认配置文件。
- 凭据和本机路径由本机应用单独保存，不写入共享模板。
- Agent 可读取 .vscode 等已有配置并生成草案，可自动调整当前任务的端口和依赖地址，并启动本地测试。
- Agent 修改共享模板时需展示差异，由用户确认；任务内自动调整不隐式回写共享模板。
- 内置浏览器按任务独立持久化 Cookie 和本地存储。首次登录由用户完成，同一任务重开后复用自己的登录状态。
- 不同任务不默认共享浏览器登录状态。任务删除时的浏览器数据清理规则尚未确定。

## 已确认的项目与任务规则

- 一个项目代表一个业务系统，维护可选仓库、服务和环境；任务选择所需仓库，之后可以追加。
- 跨仓库共享模板集中在项目配置目录并可通过 Git 管理；各电脑在应用中绑定实际仓库路径。集中维护的内容遵循上方环境变量策略，业务默认配置继续归属业务仓库。
- 各仓库可设置默认基准分支，创建任务时分别选择明确的远程分支。先 fetch 获取最新头部提交，全部获取成功后从逐仓库固定的提交建立独立分支/worktree；不使用旧本地基线，不对原检出目录执行 pull/merge/reset。获取失败保留表单和重试，不回退旧引用；追加只处理新增仓库，文件视图记录远程分支及实际创建提交。
- 中文任务名称仅用于显示；目录采用自动 `task-<8 位英文数字标识>`，默认分支为 `task/<同一短标识>` 且可独立修改。目录标识检查冲突，名称／分支修改不改变目录。
- 「本机设置」配置默认任务根目录，创建时可单次覆盖并预览 `<根目录>/<任务目录>/<仓库目录>`；任务保存实际路径，默认值变化不迁移已有任务，追加仍沿用原目录。本机路径不进入共享模板。上述界面于 2026-09-20 获用户确认，真实磁盘／Git 与跨平台行为另验。
- 重新打开任务时继续使用其原有代码。
- 完成任务后默认归档，停止服务并保留代码、会话和浏览器状态；清理是独立操作，存在未提交或未交付代码时提示处理。
- 提交、推送、合并由明确操作触发。
- 同一任务支持多个会话共享代码与运行环境。首版同时只允许一个会话执行会修改代码、配置或运行状态的操作，其他会话可阅读和分析；不同任务可并行执行，包括不同项目中的任务及其会话；用户已进一步明确跨项目并行。执行权按任务协调，切换项目不会暂停其他项目的 Agent 或服务。
- 新任务使用最新共享模板；已有任务保留已采用的版本，并提示可用更新。
- 用户或 Agent 显式应用模板更新后重新解析配置，列出需要重启的服务；编辑共享模板不直接影响运行中的服务。

## 设计建议（未确认）

### 配置与运行

- 将环境变量/远程依赖、服务启动方式、任务本地覆盖分开表示。
- 从 .vscode 导入可支持的启动方式和环境变量；对依赖特定调试扩展的部分明确显示转换缺口。
- 图形界面与 Agent 调用同一个配置解析器和服务管理入口。
- 每次启动形成可追踪的运行记录，关联代码版本、模板版本、端口及依赖去向；记录中保存凭据引用，不复制凭据明文。
- 启动环境变量按共享环境值、本机私有值、任务覆盖的顺序解析；任务自动分配的端口和依赖地址使用明确的变量绑定，同一变量存在相互冲突的绑定时报告冲突。
- 服务按自己的规则将注入的环境变量与仓库默认配置合并；PiDock 不假设所有语言/框架有相同的配置优先级。
- 所有本地服务地址确定后，注入服务声明的环境变量，再按健康条件启动；不由 Agent 猜测变量名称。
- 图形界面显示变量的生效来源及覆盖关系，敏感值保持遮蔽；让用户能解释服务为何使用某个地址。
- 每个任务管理自己的端口、日志、输出目录与进程树。共享外部数据的冲突仍需另行处理。
- 将远程依赖可达性检查纳入启动检查；依赖不可达时展示原因，不将本地启动成功等同于功能验证成功。

### 浏览器验收目标

- 用户与 Agent 操作同一个内置标签页，可以看到并接管页面。
- 优先通过有大小限制的结构化页面快照和语义定位操作控件，辅以截图和坐标操作。
- 支持导航、点击、填表、键盘操作、等待状态及截图。
- 支持获取相关控制台错误、请求失败和响应状态，以协助判断失败原因。
- 浏览器标签页显式关联任务，Agent 只获得当前任务的页面句柄。
- Cookie、登录状态与存储遵循上方已确认的任务隔离策略。
- 避免持续返回完整页面、全部日志或全部网络响应；按操作返回变化和按需查询的证据。
- 页面重载、弹窗和标签页关闭之后可识别句柄失效并恢复；用户接管时暂停 Agent 后续页面操作。
- 验证结果关联任务运行实例与代码版本，避免将旧进程或另一个任务的成功误认为当前修改验证通过。

### 技术候选

- Electron + TypeScript；pi 会话与服务进程管理运行在独立于页面界面的进程中。
- Electron 内置页面结合浏览器自动化协议；具体 Playwright/CDP 接入方式需原型验证。
- 应用管理工作区、配置与进程，通过工具暴露给 pi；AgentSession 本身不承担这些资源的持久化管理。
- 现有 devtask 的任务/worktree 生命周期设计可参考；是否复用 Go 实现尚未决定。

### 浏览器可行性核对

- Electron 的 WebContentsView 可承载可见网页，持久 session partition 可按任务分配。同一 partition 共享会话；按任务隔离并不同时意味着共享登录。
- Playwright 提供语义定位、自动等待和重试。其 connectOverCDP 仅支持 Chromium，官方说明该连接的保真度低于原生 Playwright 连接；Electron 自动化支持标为 experimental。
- 因此，Playwright 对多 WebContentsView、多 partition 的发现、准确绑定与长期稳定控制仍是候选实现，不能视为已验证能力。
- Electron webContents 提供截图、控制台事件及 debugger/CDP 通道；使用后者时要处理 DevTools 打开或页面关闭引起的 attachment 脱离。
- 远程页面不启用 Node.js，启用 contextIsolation 和 sandbox；应用能力由受控入口提供。
- 首个浏览器原型建议在 macOS/Windows 各运行两个任务页：同站点不同登录，按角色填写表单并等待异步结果，捕获一次失败 API、控制台错误与截图；人工接管后可恢复；重启后保留各自登录，关闭一个任务不影响另一个。另检查弹窗、iframe、下载及 DevTools 重连。

## 远程访问与扫码配对（2026-09-21 已确认）

远程访问保留三种入口：推荐 Tailscale Serve 作为私有访问首版，自建 PiDock Gateway 满足普通浏览器和自主托管，Funnel 仅作为实验性公网入口。三种入口共享设备授权和 PiDock 领域权限；远程可达不等于获得操作权。自建模式由桌面主动连接公网 HTTPS/WSS Gateway，不开放本机入站端口，不暴露原始 Pi RPC。

Gateway 负责登录、一次性配对交换、设备凭据、在线主机路由、断线重连、限流、撤销与审计，部署者负责 TLS、密钥、数据库、备份、升级和监控。DERP 只解决 Tailscale 网络中继，不替代这些业务职责。桌面本地生成二维码，码内只放短时单次配对凭据；手机扫码打开链接，登录后仍需桌面确认设备及权限。高风险远程终端、文件写入、能力安装和 MCP 配置默认关闭或要求本机确认。

已验证的是原型中的模式切换、Gateway HTTPS 地址与模拟连接、二维码生成及刷新失效反馈；没有启动 Tailscale、Gateway 或外部服务，也没有执行真实登录、配对、消息转发和撤销。完整边界见[规格](../.scratch/pidock-mvp/spec.md#远程访问与设备配对)和[调研记录](pi-extensibility-and-remote-access.md)。现有 15 项拆分尚未覆盖这一新增系统，需整体审阅和重排，暂不发布工单。

## 定时任务与内置模板（2026-09-21 已确认）

定时任务是任务的一种类型，而不是脱离任务的项目级规则。新建任务时选择普通或定时，进行中列表标记类型；定时任务只准备一次工作区，每次触发在同一任务内创建新的独立会话，历史会话可查看并继续对话。不同执行不继承对话上下文，但共享任务代码和运行环境。

原型提供一次性、每日、每周和五段 Cron、IANA 时区、会话权限、启停、立即运行及执行记录。已确认五个可选模板：仓库改动周报、站会主题准备、代码贡献统计、代码风险巡检、发布准备检查。每个模板含建议周期和完整默认提示词，点击「使用模板」填入后可编辑；保留项目、模型、权限、时区和工作区设置。结果如何保存、通知或发送直接写入提示词，不增加单独交付配置。立即运行在同一模拟任务内创建新会话。首版采用默认权限（需要时等待确认），由 PiDock Host 在本机运行调度器：离线期间不补跑，同一规则上一执行未结束时跳过，目标项目／Provider／模型失效时停止并提示，不静默替换。用户已确认本轮设计；尚未注册系统计划、后台唤醒或调用真实模型，运行时另行验收。

## 安装与发布（2026-09-21 已确认）

首版使用 GitHub Actions 构建和发布安装包。GitHub Release 必须同时提供 macOS arm64 的 DMG 与 Windows x64 的 EXE；只有两个目标的构建、架构、安装冒烟及签名门禁均通过后才视为完整发布。正式 DMG 需要代码签名与公证，正式 EXE 需要 Authenticode 签名；资产携带版本、平台、架构和 SHA-256 校验信息，发布凭据只进入受保护的工作流环境。具体要求与验证见[规格](../.scratch/pidock-mvp/spec.md#安装包与-github-release)和[验收计划](mvp-validation-plan.md#安装包与发布)。
