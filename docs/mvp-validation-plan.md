# 首版验证计划

功能验收与勾选统一在 [首版收口 #135](https://github.com/Leonz3n/PiDock/issues/135)，工单入口见 [父规格 #1](https://github.com/Leonz3n/PiDock/issues/1)。本页提供真实桌面验证场景，不保存第二套完成状态。当前仅整理文档与工单，产品实现仍暂停。

## 核心流程

| 顺序 | 真实桌面验证场景 | 判定重点 |
| --- | --- | --- |
| 0 | 按 [Pencil](design/README.md) 对照工作空间、任务、会话、设置与外观 | 1440×900、720×560；日间 / 夜间 / 跟随系统；52px 顶栏、浮动 Composer、模型旁紧凑推理选择；进入能力管理 / 设置分别替换为专用导航，返回保留任务 / 会话与草稿；能力管理默认 Providers，仅含 Providers / MCP / Skills，设置默认外观并含快捷键 / 语言 / 通用导航；首版不出现 Extensions / Computer Use / Browser 管理入口；旧原型 A 截图不作新版证据 |
| 1 | 新建可复用工作空间，登记多个 Git 仓库和普通目录，维护变量与分支约定；选择部分来源创建任务和多个会话 | 工作空间 → 任务 → 会话身份与持久数据一致；工作空间配置默认继承，任务可局部覆盖，私有值不泄露；重命名不改变归属，未归属任务不按路径自动认领；缺失 / 损坏明确报错，不回落样例 |
| 2 | 同仓库创建两个任务，默认自动准备各自独立 worktree，混入普通目录；另测显式已有 Git 目录和纯普通目录任务 | **两种方式都在首版**；从本次成功 fetch 后固定的提交创建，不覆盖来源未提交代码；分别展示副本路径、基线、分支与共享原目录事实；获取失败、部分创建失败、重开、路径失效可修复，不静默降级或认领其他目录 |
| 3 | 添加 / 编辑供应商，填写协议、API Key、Base URL、模型，真实对话并切换模型 / 可用推理档位 | 供应商编辑替换列表内容区；未发现模型可手填，发现成功增加下拉且保留手填；发现 / 连通失败保留输入；原生配置真正被会话加载，流式输出、停止和错误清楚，凭据不会进入日志或共享配置 |
| 4 | UI 配置 MCP、测试连接 / 启停并调用真实工具；添加 / 查看 / 启停本地 Skills 并在会话使用 | 依据目标 Pi 1.5.0（当前实际依赖仍为 1.4.0，升级归 #134）核实配置格式与能力；配置、加载和使用形成闭环；安全会话边界应用变更，来源、权限、凭据与资源回收一致；静态卡片或只写配置不算通过 |
| 5 | 在多个任务与会话中对话，读取 / 搜索 / 修改授权文件和执行命令，覆盖审批、拒绝、取消、失败、重启与草稿恢复 | 显示正确任务路径 / 分支 / 提交；工具记录与审批归原会话；只读 / 默认 / 自动执行遵循既有权限；同任务写入协调、跨任务共享真实路径协调真实有效；恢复不重放副作用；附件或引用展示与实际发送范围一致 |
| 6 | 新建、启停、编辑、立即运行定时任务，查看执行记录并继续聊结果 | 保存提示词 / Provider / 模型 / 权限 / 时间规则；固定任务工作区，每次独立会话；同任务未结束或等待审批时跳过；关窗可后台运行，退出 / 休眠不执行、不补跑；重启不重复，失效目标不静默替换 |
| 7 | 会话归档 / 恢复 / 删除，任务归档 / 恢复 / 收尾与 worktree 清理；在执行中发起操作 | 会话与任务操作分别呈现；停止 Agent 与相关执行后再处理历史；归档暂停调度，恢复不自动启用；清理前展示未提交 / 未交付内容、保留 / 导出范围并明确确认；部分失败可恢复，保留用户原始仓库 / 普通目录 |
| 8 | 正常关窗、从后台重开、明确退出、异常退出与冷恢复；在目标平台安装包中重复核心流程 | 关窗后台与明确退出分别验证；退出先中止 Agent，再回收所属子进程 / SDK；不按旧 PID 误杀资源；依赖完整、持久数据与升级保留；macOS / Windows 分别记证据，开发环境测试不代替安装验收 |

共享或重叠真实目录按 [ADR 0003](adr/0003-shared-directory-write-coordination.md) 验证，特别核对跨 Host 进程协调；任务 ID、独立进程和不同链接名均不是文件隔离证据。外部编辑器写入按 [ADR 0006](adr/0006-external-editor-writes-exempt-from-coordination.md) 明确豁免。

Git 分支规范用于命名和推送目标预览，实际提交 / 推送 / PR 以明确用户操作触发并显示目标；画板的示例文字不授权后台自动推送。工作空间变量继承不是按环境组织的服务模板或多服务编排。Pi 原生配置的文件路径、字段、MCP 传输及可热重载范围在接入时核实，不以画板示例充当 SDK 契约。

## Pi 1.5 增量验证

目标与差额见 [Pi 1.5 升级设计](architecture/pi-1.5-upgrade-design.md)。#134 验证同步依赖、工具参数转换／Host 严格校验、审批与执行参数一致、取消／截断和 SDK 会话写失败；#138 及其下游在新基线上交付。重点补充按模型提供 off／实际推理档位、请求／响应模型及费用来源、MCP Streamable HTTP 与 OAuth、Windows Skills／信任／会话路径大小写，以及大工具调用的流式预览和中文 UTF-8。上游 TUI 性能与 pi.exec 修复不替代自有 renderer／Host 实测。

#154 用 0.87.1 与 1.4.0 会话备份验证到 1.5.0 的升级、回退边界及写失败恢复；#22 对当前版本安装载荷复验。旧 1.4 测试与 0.1.6 安装证据不代表目标基线已通过。本轮未安装或运行 1.5，新增验收保持未勾选。

## 分发与证据

Windows 内部 / 自用未签名 MSI 的剩余验收见 [#22](https://github.com/Leonz3n/PiDock/issues/22)；对外签名、公证、Release 与 macOS 分发门槛见 [#80](https://github.com/Leonz3n/PiDock/issues/80)，继续暂缓。macOS 功能验证与公开分发分开记录。新 UI 与新功能需使用对应源码 / 安装载荷重新取证，旧 0.1.6 的安装记录不证明当前版本通过。

每项记录实际路径、版本 / 提交 / 产物身份、操作、预期和实际结果，并分别列出通过、失败和未测。Pencil 画板检查只证明设计结构；规则测试、内存适配器、回环模型、开发版 Electron 和安装版各自证明的边界不同。
