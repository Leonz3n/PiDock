## 阶段二：验证高风险技术点

### 内置浏览器控制

使用 Electron + WebContentsView 与候选自动化接口验证同一可见页面的控制能力。实现路线取决于验证结果，不能以“可打开网页”代替 Agent 控制通过。

验收：

1. 两个任务访问同一个试点站点，使用不同账号；登录和本地存储互不覆盖。
2. Agent 通过角色/标签定位输入框与按钮，填写表单并等待异步结果；过程在用户可见页面发生。
3. 失败时可获取相关控制台错误、失败请求状态和截图，不持续输出完整页面及全部网络内容。
4. 用户接管后暂停 Agent 的后续页面操作，显式恢复后 Agent 根据新页面状态继续。
5. 重载、弹窗、iframe、页面关闭及开发者工具开启后，目标绑定仍正确或明确报告失效并恢复。
6. 应用重启后，各任务保留自己的浏览器状态；关闭一个任务不影响另一个。
7. macOS 与 Windows 分别验收；只有实际测试通过的平台可以标记已验证。

### 环境变量与本地依赖

1. 基于仓库默认配置，导入启动方式与环境变量绑定；图形界面可编辑并显示来源。
2. 同一项目创建两个任务，都包含 B/C；各自分配本地端口，A 只连接本任务的 B/C。
3. 使用日志或可观测响应证据确认实际请求去向，不能仅检查生成的变量文本。
4. 分配端口时遇到外部占用，重新解析受影响的依赖地址或明确报告，避免继续使用陈旧地址。
5. 对构建时读取变量的前端重新构建/启动，对运行时读取变量的服务按实际规则启动。
6. 远程依赖不可达时指出具体缺口；Telepresence 的自动连接与拦截仍待后续设计。

真实试点新增的验收项：消费者需在协议改变时绑定到本任务生成物；invoice/shipment 双向依赖使用启动分组；前端 localStorage 的 BFF 地址覆盖需与任务实际目标一致；异步队列与 DTM 回调需独立用例验证，不能由同步测试代替。

### 远程访问与设备配对

1. Tailscale Serve 模式下 Host 只监听回环地址，使用两名 tailnet 用户验证 Grants；未授权用户不可访问，已授权用户仍需通过 PiDock 设备授权。
2. 自建 Gateway 使用有效公网 TLS 和桌面主动出站 WSS；模拟断网、重连、重复消息和两台主机，确认请求不会串到错误主机或绕过权限。
3. 二维码在桌面本地生成，手机扫码自动打开正确入口。检查 URL fragment 仅含随机短时凭据；使用一次、超过有效期或桌面刷新后，旧链接均被拒绝。
4. 手机完成登录和凭据交换后，桌面显示待确认设备、名称和权限。拒绝不创建设备；确认后签发独立设备凭据，撤销会终止现有连接并拒绝后续请求。
5. 默认只允许查看项目、任务、状态以及查看／发送对话；轻量管理再次确认。文件、终端、能力安装、MCP 修改和高风险配置默认关闭，并验证不能通过对话命令或原始 API 绕过。
6. Funnel 与自建 Gateway 检查登录、CSRF／重放防护、限流、审计、日志脱敏、密钥轮换和升级回滚。没有完成公网威胁测试前不得标记为生产可用。

### 定时任务

1. 新建定时任务并分别配置一次性、每日、每周和五段 Cron 规则，固定 Provider／模型、时区、新会话权限和提示词；重启后任务工作区、配置与下一次触发时间保持一致。
2. 新建时选择普通或定时，验证进行中列表类型标记；触发后在同一定时任务中创建新 Agent 会话，首条用户消息、Provider／模型及权限与规则一致，不重复创建任务工作区。
3. 连续触发同一规则时让首次执行保持运行，后一次必须跳过并记录原因；立即运行生成独立执行但不改变原下次计划时间。
4. 覆盖 Host 退出、系统休眠、时钟回拨、夏令时边界及重启恢复；错过的触发不补跑，同一预定时间不重复执行。
5. 从执行记录打开对应历史会话，检查消息、工具结果和错误，再继续对话；后续消息保留在该会话且不进入下一次触发的新会话。
6. 删除项目、停用 Provider、移除模型及使凭据失效，确认执行明确失败且不切换到其他项目或模型；历史任务、会话和用量仍可查看。

### 运行时与界面栈

1. 确认 Host 在 Bun 下启动：会话创建、工具调用、流式输出、取消与重开恢复与 Node 下行为一致，并记录实际 pi 版本与 Bun 版本。
2. 用版本匹配的 `bun build --compile` 产出 Host 单文件二进制，在未安装 Node 与 Bun 的干净目标系统上启动并完成一次完整任务操作。
3. 验证渲染层由 React、Tailwind CSS 与 TanStack 构建后能被 Electron 正确加载，且与 Host 的接口在同一任务上返回一致结果；不以静态草稿或内存模拟代替。
4. 在 Bun 运行时下验证页面自动化客户端对可见页面的定位、等待与错误证据；若不可用，记录替代方案与其代价，不静默回退到另一个隐藏浏览器。
5. 记录 Bun 编译产物的体积、启动时间与跨平台签名要求；升级 pi 后重测运行时兼容性，因为 pi 的 `engines` 只声明 Node。

### 安装包与发布

1. 以版本标签触发 GitHub Actions，分别在目标构建环境生成 macOS arm64 DMG 与 Windows x64 EXE；检查应用内部版本、文件名、实际二进制架构和标签一致。
2. 双平台任务均完成依赖安装、构建、架构检查、签名检查和安装冒烟后才允许发布；模拟任一任务失败或产物缺失，确认不会生成被标记为完整的 GitHub Release。
3. Release 同时提供两个安装包及 SHA-256 校验值，并能从资产追溯到工作流运行和唯一提交；重新运行不得用不同源码静默覆盖同名正式资产。
4. 在干净 macOS ARM64 与 Windows x64 目标系统从 Release 下载并安装，验证首次启动、重开、覆盖升级及卸载。macOS 检查签名和公证，Windows 检查 Authenticode 签名；升级／卸载不删除应保留的用户数据。
5. 验证发布凭据仅在受保护的标签／environment 流程可用，普通分支和外部 fork 无法读取或借工作流输出泄露签名材料。

以下为建议顺序，不是已分派的实现工单。

| 步骤 | 可使用的结果 | 关键验收 |
| --- | --- | --- |
| 运行时与骨架 | Electron 桌面壳、Bun Host 与 React／Tailwind／TanStack 渲染层跑通 | 干净系统不预装 Node／Bun 也能启动；pi 在 Bun 下会话行为一致；静态草稿未被提升为实现代码 |
| 项目与任务 | 配置任务根目录，注册仓库，从最新远程基线创建任务，恢复与追加仓库 | 中文名称与英文数字目录分离；默认根目录／单次覆盖与原路径恢复；两任务 worktree/分支独立；从本次 fetch 的提交创建，获取失败不回退，部分创建失败可恢复 |
| 环境与服务 | 图形化维护共享模板/私有配置，解析任务覆盖并启动服务 | UI 与 Agent 使用同一结果；默认配置文件保持由业务仓库维护；依赖指向正确 |
| Agent 执行 | pi 会话管理，文件浏览、内置终端及服务工具 | 同任务写操作串行，同项目及跨项目的不同任务并行；切换项目不暂停隐藏任务的 Agent／服务；任务锁覆盖整个有副作用的执行过程 |
| 浏览器验证 | 控制真实页面、查看请求错误与日志、形成验证记录 | 可关联到当前任务的运行实例和实际代码状态，识别服务未重启或使用旧构建 |
| 远程访问 | 启用 Tailscale Serve 或自建 Gateway，配对并撤销移动设备 | 私网／公网入口边界正确；短时单次二维码可扫码打开且不可复用；设备权限不放宽会话、任务或高风险操作约束 |

| 生命周期 | 后台运行、明确退出、归档和清理 | 仅停止所属进程及其子进程；持久状态可恢复；跨平台分别验证 |

内置终端可执行有副作用的命令，不能仅凭会话名称宣称只读。只读会话的工具范围、人工终端与 Agent 写操作协调、子进程归属，需要在具体实现设计中处理。

## 用户界面草案

- 视觉：工作台自有界面的强调、状态及图表不使用绿色；当前为中性灰白底和蓝色强调。各处 π 标记居中，跨平台检查字体和尺寸变化。A 对话优先已作为实现基线，B/C 保留历史对照；正式界面按 React、Tailwind CSS 与 TanStack 重建，不以静态草稿为实现起点。
- 项目页：仓库绑定、服务定义、按环境切换的变量表，支持私有值及有效值来源查看。
- 新建／追加任务：中文显示名称与英文数字目录标识分离；本机默认根目录可配置并持久化，新建可单次覆盖且实时预览，修改默认值后已有任务重开／追加仍使用原路径。检查目录冲突、标识碰撞、权限及 macOS/Windows 路径。
- 远程最新基线：用可控远程仓库制造本地分支和跟踪引用过期，验证逐仓库 fetch 后从实际最新提交建 worktree；远程可不同，文件面板展示来源与提交。全部获取成功前不建工作副本；覆盖获取失败保留表单与重试、认证失败、远程分支删除／强推，以及并发获取后仍使用各自固定提交。确认原检出目录未提交工作与已有任务代码不变。这些是正式验收项，原型模拟不能替代执行结果。
- 任务页：仓库与分支、实际目录和创建基线、环境版本、本地/远程服务选择、健康状态，以及会话。
- 应用设置：多个 Provider 配置、可用模型及本机认证；对话内选择 Provider/模型，显示上下文窗口、占用和执行状态。
- 会话权限（2026-09-21 已确认）：检查「+」后的权限入口与三档说明、键盘／窄栏可用、会话独立保存和重启恢复，切换保留文字与图片草稿。以真实工具验证只读无法通过文件、命令、浏览器或派生执行绕过；默认权限的命令／浏览器操作先询问且拒绝／取消不执行；自动执行仍遵循任务范围、共享模板确认及同任务写锁。检查后续请求采用新选择，在途请求／已启动 Subagent 保留启动时权限，恢复不重放操作。原型选择行为不替代此验收。
- 对话浮层：模型按 Provider 分组并支持搜索/键盘选择；推理只列模型可用档位，标明当前/默认值；上下文入口显示占比，详情区分占用与累计消耗，压缩不减少累计。覆盖三种候选布局中的位置与草稿保留。
- 超限切换：以 24.8k 会话与 16k 模型为例，选择入口置灰且实际切换操作拒绝，原模型、历史和草稿保留，不自动压缩后切换。覆盖 Provider 页面和 `/model`，以及新会话、明确压缩后重新选择、占用待更新和数值边界；后续以真实运行时口径验证，不能只依赖原型示例数据。
- 对话输入：`@` 引用任务文件/目录及所选代码，`$` 搜索调用技能，`/` 提供会话、模型、压缩和用量等命令；候选可用键盘操作，同名条目明确来源，中文输入法确认不误发送。验证实际读取当前任务 worktree、忙碌命令遵循执行协调，以及草稿恢复后不会重新执行。
- 用量页：单次调用与会话明细，以及按时间、项目、任务、Provider 和模型的 Token 汇总；估算、缺失与实报数据有明确区分。
- 工作区域：默认关闭工具区，通过任务顶部或对话内操作按需打开运行、文件、终端、浏览器和日志；仅显示已打开标签，可逐个关闭或收起，关闭最后一个后释放对话空间。各面板始终显示归属任务；分别验证关闭面板不隐式结束服务、终端进程或清理浏览器状态。
- 输入框布局与附件：左下角「+」调用真实系统文件选择器，检查多选、取消、显示名称和移除；模型选择位于右侧、发送按钮之前。不常驻展示符号按钮，键入 `@`、`$`、`/` 的补全仍可用。原型文件选择不读取或上传内容，正式系统须另验来源、类型、大小与实际发送范围。
- 远程访问（2026-09-21 已确认）：检查 Tailscale 私有访问、自建 Gateway 与实验性 Funnel 的配置边界；生成二维码后手机扫码自动打开，旧码在使用、过期或刷新后失效；设备独立授权和撤销。原型模拟不能替代真实网络、认证、路由、限流和审计验收。
- 归档入口与清理入口分别呈现；清理前展示涉及的代码、会话及浏览器数据。

## 混合目录与软链接验收

2026-09-21 已确认交互方案；以下为正式实现验收计划，当前仅有 UI 模拟证据。

- 同项目混选 Git 与普通目录、仅选普通目录；均在配置根目录建立 ASCII 任务文件夹，中文显示名不改路径。纯目录任务无需 Git／环境，pi 从统一任务目录启动。
- 创建预览与磁盘上的 worktree／链接路径及目标一致；单次覆盖、追加、重开保持来源快照和稳定链接名，已有 Git 基线及运行资源不变。
