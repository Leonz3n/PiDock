### 可配置任务根目录与远程最新基线

用户进一步明确要求：可配置任务根目录，创建时在其下建立任务子目录；基线可能过期，必须获取远程最新 HEAD 后再创建 worktree。用户随后确认此部分，以下规则成为本轮设计基线。

- 原型新增「本机设置 → 默认任务根目录」。新建表单带入默认值，并允许本次修改；路径实时预览为根目录 / 自动任务目录 / 仓库目录。本机设置不进入共享模板，修改默认值不迁移已有任务；追加仓库使用任务保存的原路径。
- 各仓库明确填写远程基线，例如 `origin/main`、`upstream/release/v2`。主操作为「获取最新基线并创建／添加」：先 fetch 对应远程分支并解析此次获取的提交，再由该提交建立独立分支/worktree；不能直接采用缓存的远程引用或本地旧分支，也不对原检出目录执行 pull/merge/reset。
- 创建流程先完成所选仓库的远程获取，再创建工作副本；远程获取失败时停留表单、指出仓库并提供重试，不静默回退旧基线。追加只处理新增仓库，不更新已有工作副本。正式实现仍须处理后续创建阶段的局部失败及恢复。
- 每个任务记录实际根目录，每个仓库记录远程、分支与创建提交；文件面板展示来源。这里的“最新”指创建准备阶段此次 fetch 获取的提交，不能保证远程在后续步骤中不再推进。真实实现需要检查路径可写性、目录冲突、远程存在性和分支删除／强推，并记录完整提交身份。

浏览器已检查默认目录保存与带入、单次覆盖和路径预览、`upstream/release/v2` 保存回显、模拟获取失败不创建任务且保留表单、重试成功、追加 `apis` 后保留既有目录和基线。语法检查通过；目录和提交仅为内存示例，未执行磁盘、Git 或认证操作。Windows 路径与真实系统目录选择尚未验收。本轮确认不等于真实运行验证通过。

## 手机远程访问与代理（2026-09-21 已确认）

用户希望配置远程代理服务器，在手机网页查看项目、任务和对话，并进行简单管理与对话。本轮新增「远程访问」一级页面及手机视图预览：

- 配置的是 PiDock Gateway，不是「Pi 远程服务器」。本机 PiDock 主动建立出站 WSS，手机经认证 Gateway 访问经过授权的 PiDock 领域 API；不开放本机入站端口，也不把 Pi 的 stdio RPC 或实验性 remote harness 暴露到公网。
