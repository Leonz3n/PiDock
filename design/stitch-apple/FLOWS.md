# 核心流程与状态边界

这些约束用于连屏与状态设计。以 GitHub #135 为规格入口；本文件只整理设计所需行为，不另建工单系统。例子均为虚构设计数据。

## F01 · 项目 → 任务 → 会话

```text
选择 / 新建项目
  → 选择已有来源（Git 仓库、普通目录）
  → 新建任务：目标、普通 / 定时、每个来源的目录方式
  → 审阅实际路径与共享边界
  → 来源准备
     ├─ 全部成功 → 新会话空态 → 明确选 Provider/模型 → 发送
     └─ 部分失败 → 保留已完成来源 → 查看原因 → 修复/恢复准备
```

Git 已有目录和普通目录会修改原文件；独立 worktree 只隔离那个副本。混合来源任务不能标注为全部隔离。fetch 失败不回退旧基线冒充成功；任务重开沿用绑定，目录移动或身份不符进入修复状态。项目、任务和会话的身份不由显示名称或路径猜测。

## F02 · 会话执行、停止与审批

```text
就绪 → 编辑当前会话草稿 → 发送 → 执行中
  ├─ 正常结束 → 结果留在本会话 → 继续对话
  ├─ 停止 → 停止中 / 资源回收 → 已停止（已完成操作不回滚）
  ├─ 权限确认 → 展示本次操作/目标/载荷/影响
  │    ├─ 批准一次 → 校验该请求仍有效 → 执行 → 记录结果
  │    └─ 拒绝 / 过期 → 不执行 → 保留可解释记录
  └─ 失败 → 原因 + 已完成范围 + 输入/引用保留 → 明确恢复动作
```

同任务的另一会话可继续编辑独立草稿，不能绕过未结束执行或审批开始冲突操作。其他独立任务不受全局锁定。修改模型/权限要等安全边界，历史消息保留实际使用的模型。网络失败不能等同于“外部操作未发生”，副作用结果未知时先核对，恢复不能盲目重放。

## F03 · 会话归档、恢复与删除

```text
会话操作
  ├─ 新建 → 新身份 + 空对话 + 独立草稿
  ├─ 归档 → 如在途先停止与回收 → 历史归档（非删除）
  ├─ 恢复 → 可查看/继续（不自动运行）
  └─ 删除 → 展示历史/草稿影响 → 确认
           → 如在途先停止与回收 → 删除指定记录
           → 任务与文件保留；定时记录标记会话已删除
```

不提供含糊的“清空”按钮同时承担新会话、删除会话和清理目录。最后一个会话删除后保留任务，提供新会话入口。重命名和归档不会把草稿交给另一会话。

## F04 · 定时任务与独立结果

```text
定时任务 → 编辑规则（提示词 / Provider+模型 / 时间+时区 / 权限）
  → 保存为暂停 → 用户启用
  → 触发 / 立即运行
     ├─ 任务已归档 → 阻止执行
     ├─ 同任务有未结束执行/审批 → 跳过，记录原因
     ├─ 配置/凭据/路径失效 → 明确失败，不替换目标
     └─ 条件成立 → 同一个任务工作区创建新会话 → 执行结果
                   → 从历史打开这个会话 → 继续聊
```

运行期间调度；关窗可后台继续；明确退出或休眠不执行、不补跑、不自动唤醒。一次触发一次独立会话，不继承上次对话。保存默认暂停是当前设计建议；不得把“保存”与“已经执行”混为一谈。下次运行预览需真实规则计算；未知时明示。编辑规则不重置已有执行、审批或历史归属。

## F05 · 配置 → 加载 → 会话使用

| 类型 | UI 配置 | 可见运行状态 | 会话中的闭环 |
| --- | --- | --- | --- |
| Provider | 名称、endpoint、本机私有凭据、模型 | 可用/验证中/失败/凭据失效；保存与可用分开 | 明确选 profile+model；实际当轮身份保留 |
| MCP | 名称、transport、command/URL、授权配置 | 停用/连接中/连接成功/失败及原因 | 能检查调用的工具、来源与授权结果 |
| Skills | 本地来源、名称、加载设置、启停 | 已加载/未加载/失效及原因 | `$` 选择 → 带来源的草稿 chip → 本轮使用 |

配置在安全会话边界生效；不要在执行中突然替换连接或凭据。无真实连接时不能显示为已验收可用。设计图用明确的示例数据标识，生产界面用真实状态。

## F06 · 任务归档与清理

```text
归档任务 → 停止在途执行 / 回收资源 → 暂停规则 → 保留历史与来源
  ├─ 恢复任务 → 可继续使用（不自动启动、不重新启用规则）
  └─ 清理 → 展示逐项清单与未交付修改
           → 明确保留代码 / 原始来源 / 将移除的记录
           → 用户确认 → 先核验代码保留，再移除受管资源
           ├─ 成功 → 回执与保留位置
           └─ 部分失败 → 保留登记，逐项修复，不宣称整体成功
```

普通目录、已有工作目录和原始仓库永不因任务清理而删除。独立 worktree 有未提交/未交付修改时须保护；保留失败不能继续删除。清理不同于可逆归档。复杂导出系统不作为本设计新增前置。

## 状态画板最低覆盖

| 情况 | 文案必须包含 | 主要下一步 |
| --- | --- | --- |
| 没有项目/来源/会话 | 缺少什么，不用假数据填充 | 创建对应实体 |
| worktree 准备失败 | 具体来源、失败步骤、已保留内容 | 修复 / 恢复准备 |
| 路径身份异常 | 绑定和当前目录不匹配 | 用户明确修复绑定 |
| 任务被另一个会话占用 | 正在执行/审批的会话归属 | 查看该会话 / 继续写草稿 |
| 待确认 | 操作、目标、载荷、影响、有效性 | 批准一次 / 拒绝 |
| 停止中 | 等待取消与资源回收 | 等待，禁止重复破坏动作 |
| 模型/凭据失效 | 配置名称、原因、保留输入 | 修复或明确重选 |
| MCP 连接失败 | 原因、配置状态 | 编辑 / 重新连接 |
| 定时跳过 | 原因、触发时间、任务 | 查看当前会话 |
| 会话已删除 | 原执行记录存在，原会话已移除 | 查看记录，禁用失效跳转 |
| 任务清理部分失败 | 成功/失败项目、代码保留位置 | 修复失败项 |
