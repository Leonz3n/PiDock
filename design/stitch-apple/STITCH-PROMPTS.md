# Google Stitch 可复制提示词

在同一个 Stitch 项目里逐屏设计。先提供全局提示词和 DESIGN.md，再一次给一屏提示词及对应参考图。下面是设计输入，不依赖某个 Stitch 导入按钮或特定模型；若当前版本不能直接读取 Markdown 文件，就粘贴全局提示词和相关段落。上传动作由用户自行完成。

## 0 · 全局提示词

```text
请为 PiDock 设计简体中文的桌面 Agent 工作台，面向 macOS 与 Windows。产品围绕“项目 → 任务 → 会话”组织本地 Agent 工作，任务可混合多个 Git 仓库与普通目录。首版必须同时支持已有目录与独立 Git worktree。

以附件 DESIGN.md 为设计系统，以 SCREENS.md / FLOWS.md 为页面和交互边界。视觉偏简洁 Apple 桌面工具、扁平、灰白、中性色和单一蓝色强调。参考当前 A 版初稿改善，不必逐像素复制。主画面突出对话，任务信息默认关闭。不要改成营销网站、KPI 仪表盘、开发者 IDE 或多面板控制台。

核心配色：白色 #FFFFFF，侧栏 #F6F6F8，辅助表面 #FBFBFD / #F3F4F7，主文字 #24262B，辅助文字 #555B66，必要元信息 #6F7682，蓝色 #2768DF，选中底 #EAF0FC，分隔线 #E9E9ED。运行蓝色、等待琥珀、失败红色、完成/归档中性灰蓝；任何产品界面均不要使用绿色。用文字表达状态，颜色只辅助。

字体建议 Inter + Noto Sans SC / 系统字体，路径与分支用等宽。正文 14px、元信息至少 12px、主要标题 24–26px。修复初稿小字对比度，不要照搬微小标签。细分隔线、6–12px 小圆角，普通区域无阴影。不要玻璃拟态、渐变、霓虹、装饰插画或 emoji 图标。

主画板 1440×900，另给 720×560 最小桌面窗口。A 布局：238px 项目任务侧栏 + 白色对话画布，58px 顶栏，约 760px 阅读列，底部输入，任务详情按需打开。窄桌面收起导航时仍保留全部管理入口。不设计手机产品。

固定首版范围：项目/来源/任务/多会话，已有目录和 worktree，Provider/MCP/Skills，定时任务与独立运行历史，会话新建续聊停止归档恢复删除，任务归档与安全清理。共享原目录必须明确，不能把整个混合任务称为文件隔离。删除会话不能删除任务与文件。

不添加：终端或命令输入、内置浏览器、文件树/独立 Diff 工作台、服务编排、环境模板、端口配置、复杂用量报表、远程/设备配对、移动端、Packages/Extensions 市场、团队/计费/云部署。对话中的只读 Agent 工具记录可以保留。

所有附件都是内存原型的示例数据和布局参考，不是验证成功的事实。不要把 A/B 切换器、DESIGN REVIEW 底栏、模拟失败按钮或调试编号加入产品。未知数据写“未知/不可用”，不虚构成功、提交或下次执行时间。

先生成 S01 任务对话主屏。完成后说明：相较初稿改善的三处，以及保留的关键产品规则。然后等待我给下一个页面提示词。
```

## 4 · S04 创建任务

附 `reference/04-create-task.jpg`。

```text
设计新建任务表单/抽屉：任务名称、普通/定时类型、多选 Git 仓库与普通目录。每个 Git 仓库分别选择“已有目录”或“独立 worktree”；worktree 有基线分支、目标任务分支和独立路径预览。普通目录固定为共享原文件。支持只选普通目录。
不要把 worktree 标为“即将推出”。不要只设一个会误导普通目录已隔离的全局隔离开关。创建前清晰预览每项最终路径与共享事实；提交以后进入逐来源准备结果。精简长表单但保留可审阅的风险边界。
```

## 5 · S05 失败恢复

附 `reference/05-preparation-failed.jpg`。

```text
设计来源准备状态：一个 worktree 已准备成功，另一个仓库 fetch 失败，普通目录绑定保留。逐项列出状态、原因和实际路径，阻止未完成来源上的执行；用户可以修复/恢复失败项，不丢已准备内容。
失败不得静默退回旧基线。补充“路径已移动 / 身份不符”修复状态，要求明确确认绑定，不能自动认领其他目录。不要用假的整体进度百分比或“全部成功”掩盖失败。
```

## 6 · S06 会话管理

附 `reference/06-sessions.jpg`。

```text
设计全部会话搜索面板，分未归档/已归档，展示名称、活动和状态。顶部最多四个会话标签，超过四个仍使当前会话可见。每个会话的草稿、模型、权限和历史独立。
提供新建、重命名、归档、恢复、删除；删除确认明确只移除指定历史和草稿，任务、其他会话和目录均保留；定时记录保留“会话已删除”。在途执行先停止和回收再归档/删除。不要提供一个含糊的“清空”按钮同时清对话和删目录。
```

## 7 · S07–S08 定时任务

附 `reference/07-schedules.jpg`、`reference/08-schedule-editor.jpg`。

```text
设计定时任务列表、规则编辑、最近执行。编辑字段：名称/提示词、一次性或周期、时间、时区、Provider+模型、权限、启停。每次触发在同一任务工作区创建独立会话，结果可以“查看并继续聊”。不要把定时执行设计成跨次复用一个聊天上下文。
给三种记录：成功且能打开原会话；同任务有未结束执行/审批而跳过并写明原因；凭据/模型/目录失效而失败，不能静默换目标。原会话删除时保留记录并关闭失效跳转。
明确：应用运行时调度，关窗可后台继续，退出/休眠不执行、不补跑、不自动唤醒。新规则保存默认暂停是本轮设计建议，保存、启用和立即执行分别表达。未知下次运行时间不能造值。
```

## 8 · S09 Provider

附 `reference/09-providers.jpg`。

```text
设计设置中的“模型服务”：Provider profile 名称、服务地址、私有凭据状态和替换/移除入口、模型列表，支持添加编辑移除。凭据只用占位，不展示真实密钥。不要把“保存配置”设计成“连通验证已通过”。
补充错误/不可用状态，并设计回到会话明确选这个 profile+model 的过程。同一模型可由多个 profile 提供，选择器需可区分。执行中不突然换模型，历史消息保持当轮实际模型。无需模型市场、团队账单或复杂 token 报表。
```

## 9 · S10 MCP

附 `reference/10-mcp.jpg`。

```text
设计“MCP 连接”：列表、添加/编辑、transport（stdio / HTTP）、命令或服务地址、启停、连接状态、失败原因和修复入口。补充连接中、已连接、已停用、连接失败四态。不要只用一个开关来表示配置与运行状态。
给一张会话内调用 MCP 工具的只读记录卡，能看工具名称、来源、授权结果与输出摘要。保存配置不等于真实加载，工具仍须授权。不要新增通用 Packages/Extensions 商店或远程配对。
```

## 10 · S11 Skills

附 `reference/11-skills.jpg`。

```text
设计 Skills 列表：本地来源、名称、说明、启停与加载状态。添加本地来源后，加载失败需具体原因。设计“输入 $ → 搜索技能 → 带来源 chip 加入当前会话草稿 → 本轮使用”的闭环；chip 可查看来源并移除。
同名技能必须能区分来源，禁用技能不出现在下一轮选择。不要做装饰性的技能卡片商店。配置变化在安全会话边界生效。
```

## 11 · S12 归档与清理

附 `reference/12-cleanup.jpg`。

```text
设计任务归档列表和清理确认。任务归档会停止在途执行、暂停定时规则；恢复后不自动启动或重新启用。会话归档/删除与任务归档/清理是独立动作。
清理清单逐项说明：共享原仓库/已有工作目录/普通目录始终保留；独立 worktree 如有未提交或未交付修改，先保护代码并展示保留位置；明确会话/草稿等记录的移除范围。补充清理部分失败的逐项恢复和回执。禁止用“删除一切”或保留失败后仍整体成功。
```
